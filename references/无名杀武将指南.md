## 第 0 节 · 给没玩过的人的最短路径

如果你只想尽快给朋友做一个能进游戏的武将，需要做三件事：

1. **在 `extension/` 下新建一个文件夹**（比如 `extension/朋友DIY/`）。
2. **放三个文件**：`info.json`、`extension.js`、`character.js`（模板见 [第 4 节](#第-4-节打包成一个扩展官方推荐路径)）。
3. **把文件夹压成 zip 拖进游戏窗口**装好（见 [4.4](#44-怎么装进游戏)）。

技能语法按 [第 3 节](#第-3-节技能怎么写) 的模板修改即可。

## 第 1 节 · 无名杀是什么

### 1.1 它和三国杀的关系

无名杀（noname）是**三国杀的免费开源实现 + 扩展平台**。核心玩法就是三国杀：身份局（主公/忠臣/反贼/内奸），武将各有体力和技能，用牌堆里的牌战斗。

但它比三国杀官方多很多：几十个武将包、多种模式（国战、对决、斗地主、战棋、塔防……），而且**从代码层面就为「玩家自己加武将」设计好了机制**——这正是你要做的事。

关键点：**你不需要会玩游戏，也能写出正确的代码**。因为武将的技能本质上就是「监听某个时机 → 满足条件 → 执行一段效果」，是一套纯事件驱动的规则，照模板填写即可。但**要设计得好玩、平衡，就必须懂游戏**，这部分建议让朋友（玩过的人）来出创意，你（或我）负责翻译成代码。

### 1.2 一局游戏怎么跑：六个阶段

每个角色的回合按固定顺序走六个阶段，源码里的权威定义在一行：

```js
phaseName = ["phaseZhunbei", "phaseJudge", "phaseDraw", "phaseUse", "phaseDiscard", "phaseJieshu"];
```
— `src/noname/library/index.js:14870`

| 顺序 | 中文 | 代码名 | 干什么 |
|---|---|---|---|
| 1 | 准备阶段 | `phaseZhunbei` | 一般什么都不做，是技能插入的时机 |
| 2 | 判定阶段 | `phaseJudge` | 结算自己判定区的延时锦囊（乐不思蜀、闪电等） |
| 3 | 摸牌阶段 | `phaseDraw` | 默认摸 2 张牌 |
| 4 | 出牌阶段 | `phaseUse` | **核心阶段**，使用手牌（杀、锦囊、装备） |
| 5 | 弃牌阶段 | `phaseDiscard` | 手牌超过体力值就要弃到体力值 |
| 6 | 结束阶段 | `phaseJieshu` | 回合结束，很多技能在这里收尾 |

### 1.3 核心资源与卡牌

- **体力（hp）**：归零就进入濒死，没人救就死亡。武将牌上写数字，比如「4」就是 4 点体力。
- **手牌上限**：默认 = 当前体力值（所以残血会弃牌，这就是「卖血流」技能的收益逻辑）。
- **基本牌**：`sha`杀、`shan`闪、`tao`桃。
- **锦囊牌**：`wuxie`无懈可击、`juedou`决斗、`guohe`过河拆桥、`shunshou`顺手牵羊、`wuzhong`无中生有、延时锦囊等。
- **装备牌**：武器（影响攻击范围）/防具/坐骑。
- **判定**：翻牌堆顶一张牌，按花色/点数决定结果（闪电劈不劈、乐不思蜀生不生效）。

### 1.4 常见术语对照

| 玩家口语 | 代码里的说法 |
|---|---|
| 摸牌 | `player.draw()` |
| 造成伤害 | `player.damage()` |
| 回复体力 | `player.recover()` |

| 获得牌 | `player.gain()` / `player.gainPlayerCard()` |
| 弃牌 | `player.discard()` |

## 第 2 节 · 武将在代码里长什么样

### 2.1 最小可用的武将

```js
const characters = {
  // ↑ 这个 key（武将 ID）是全游戏唯一的，之后图片、翻译、技能都靠它关联
  my_hero: {
    sex: "male",          // male / female
    group: "shu",         // 势力：wei / shu / wu / qun / jin / shen / key
    hp: 4,                // 体力
    skills: ["my_skill_a", "my_skill_b"],  // 技能 ID 数组
  },
};
```

这是**新式对象写法**。也兼容老式数组写法，但不推荐新写：
`[性别, 势力, 体力, 技能数组, 额外标记数组]`
（实例见 `extension/整合包/character/character.js:6`）

### 2.3 `hp` 的三种写法

解析逻辑在 `src/noname/get/index.js:979`（`infoHp` / `infoMaxHp` / `infoHujia`）：

```js
hp: 4              // 体力 4 / 上限 4
hp: "4/6"          // 体力 4 / 上限 6   ← 也能写成 hp: 4, maxHp: 6
hp: "4/6/2"        // 体力 4 / 上限 6 / 护甲 2
hp: "∞"            // Infinity（BOSS 用）
```

> 实例：`diy_wenyang` 用的是对象写法的 `hp: 4, maxHp: 6`（`src/character/diy/character.js:119-125`）。

**体力不能大于上限 —— 超了会被引擎压回去。** 想写 `hp: "6/4"` 让武将开局 6 血、
上限 4，引擎不会报错，但玩家初始化时 `init()` 末尾会调 `$update()`
（`src/noname/library/element/player.js:3621-3622`），而 `$update()` 开头就是
`if (this.hp >= this.maxHp) this.hp = this.maxHp`（`player.js:4618`；`update()` 同规则，
`player.js:4599`）—— 结果还是 4/4。想开局更耐打，用第三个数字的**护甲**：

```js
hp: "4/4/2"   // 体力 4 / 上限 4 / 护甲 2
```

（护甲在 `player.hujia`，与体力分开计算，不受这条上限约束。）

### 2.4 `names` 的 `|` 语法

`names` 是给**姓氏/名字拆分**用的（用于国战等需要称呼姓+名的场合）。解析代码在 `src/noname/get/index.js:906`（`get.characterSurname`）：

```js
names: "司马|懿"        // 姓"司马"，名"懿"
names: "甘|null"        // 姓"甘"，名用默认值（"某"）
names: "null|null"      // 全默认
names: "孙|綝-孙|峻"    // 用 - 分隔多套：两套名字（孙綝 / 孙峻）
```

**不写 `names` 也完全没问题**：源码会自动按「第一个字 = 姓，其余 = 名」切分（`get/index.js:908-911`）。所以新手直接省略。

## 第 3 节 · 技能怎么写

### 3.1 技能对象的结构

技能就是 `lib.skill` 这张表里的一项：

```js
const skills = {
  my_skill_a: {
    audio: 2,                        // 语音编号，可省略
    trigger: { player: "damageEnd" },// ① 何时触发
    filter(event, player) {          // ② 能不能触发
      return event.num > 0;
    },
    async content(event, trigger, player) {  // ③ 效果本体
      await player.draw();
    },
    ai: { /* 可选：影响电脑决策 */ },
  },
};
```

技能名（`my_skill_a`）是全局唯一的 key，同时默认用作翻译 key：`lib.translate.my_skill_a`（技能名）和 `lib.translate.my_skill_a_info`（技能描述）。

### 3.2 六类技能与模板

#### (a) 触发技 —— 最常用

```js
stdqingjiao: {
  audio: 2,
  trigger: { player: "damageEnd" },
  filter(event, player) {
    return event.num > 0;            // 受到>0点伤害才发动
  },
  check(event, player) {             // AI 是否愿意发动
    return true;
  },
  async content(event, trigger, player) {
    await player.draw();
  },
},
```

真实实例：`jianxiong`（奸雄，受到伤害后获得伤害牌）— `src/character/standard/skill.js:331`。

#### (b) 带代价的触发技

`cost` 负责问玩家「要不要发动」并把结果写进 `event.result`：

```js
my_skill: {
  trigger: { global: "phaseJieshuBegin" },
  filter(event, player) { return event.player != player; },
  async cost(event, trigger, player) {
    event.result = await player
      .chooseToDiscard(get.prompt2(event.skill), "h")
      .set("ai", card => 6 - get.value(card))
      .forResult();
  },
  async content(event, trigger, player) {
    await trigger.player.damage();
  },
},
```

#### (c) 主动技 —— 出牌阶段自己点按钮

```js
my_active: {
  audio: 2,
  enable: "phaseUse",
  usable: 1,                        // 每阶段限一次
  filter(event, player) { return player.countCards("h") > 0; },
  filterCard: true,
  selectCard: 1,
  filterTarget(card, player, target) { return player != target; },
  check(card) { return 6 - get.value(card); },   // AI 选牌
  async content(event, trigger, player) {
    await event.target.damage();
  },
},
```

`enable` 的合法取值：类型定义上只有 `"phaseUse"`、`"chooseToUse"`、`"chooseToRespond"`、`"chooseCard"`（`src/typings/type.d.ts:875-877`）。
但运行时其实更宽松——**也能写函数**，且 `"phaseUse"` 判的是 `event.type === "phase"` 而不是名字全等（`src/noname/library/index.js:11114-11131`）。
新手按类型定义那 4 个写就够了。

#### (d) 视为技 —— 把牌当别的牌用
```js
my_viewas: {
  enable: ["chooseToUse", "chooseToRespond"],
  filterCard(card) { return get.color(card) == "red"; },
  viewAs: { name: "sha" },
  viewAsFilter(player) { return player.countCards("hs", { color: "red" }) > 0; },
  position: "hs",                   // 从手牌+装备区选
  prompt: "将一张红色牌当杀使用或打出",
  check(card) { return 5 - get.value(card); },
  ai: { respondSha: true },
},
```

#### (e) 规则修改技（`mod`）—— 不需要 trigger/content

```js
mashu: {                            // 马术：计算距离时-1
  mod: {
    globalFrom(from, to, distance) { return distance - 1; },
  },
},
```
真实实例：`src/character/standard/skill.js:1489`。

#### (f) 组合技（`group` / `subSkill`）

```js
my_combo: {
  group: ["my_combo_part1", "my_combo_part2"],
  subSkill: {
    part1: { /* 会自动展开成 lib.skill.my_combo_part1 */ },
    part2: { /* ... my_combo_part2 */ },
  },
},
```

[警告] **关键前提**：`subSkill` 只是把子技能**注册**进 `lib.skill`，**不会让你自动拥有它们**。必须同时写进 `group`（或运行时用 `player.addTempSkill("主技能_子技能")`）。漏写 `group` 是新手最常见的「技能写了但没用」原因。

### 3.3 触发时机 —— 权威模型（重点）

无名杀的时机名**不是一张死清单**，而是一条生成规则。权威定义在
`src/typings/type.d.ts:857-872`：

```
最终时机名 = 事件名 + 后缀
后缀 ∈ { Before, Begin, End, After, Skipped }
```
— `type.d.ts:868-869`

例如事件 `damage` 可以派生出 `damageBefore` / `damageBegin` / `damageEnd` / `damageAfter`；
事件 `phaseUse` 派生 `phaseUseBefore` / `phaseUseBegin` / `phaseUseEnd` / `phaseUseAfter`。

**常用事件名**（完整列表见 `type.d.ts:860` 的 `EventWithTrigger`）：

`damage`、`die`、`dying`、`draw`、`recover`、`loseHp`、`gain`、`lose`、`discard`、`judge`、`useCard`、`useSkill`、`respond`、`phaseZhunbei`、`phaseJudge`、`phaseDraw`、`phaseUse`、`phaseDiscard`、`phaseJieshu`、`phaseBegin`、`phaseEnd`、`phaseOver`、`roundStart`、`gameStart`、`chooseToUse`、`chooseToRespond`、`chooseToDiscard`、`chooseTarget`、`gainMaxHp`、`loseMaxHp`、`changeHp`、`recast`、`link`、`equip`、`cardsGotoPile`…

**另有手动触发的信号**（不是「事件名+后缀」，直接写在 `type.d.ts:858` 的 `Signal_Trigger`）：

`damageBegin1` ~ `damageBegin4`、`damageSource`、`changeSkillsBefore/After`、`phaseAny`、`useCard0/1/2`、`shaDamage`、`shaHit`、`shaMiss`、`skillAfter`、`triggerAfter`、`judgeFixing`、`compareFixing`、`yingbian`、`zhuUpdate`、`roundStart` …

> 实践建议：**不要背清单**。想监听「我受到伤害后」就写 `damageEnd`，想监听「我受到伤害时（数值未定）」写 `damageBegin` 或 `damageBegin3`。写错时游戏会不触发——这就是需要对照源码/已有技能的地方。

**README 级别的常用时机速查**：

| 想做的事 | 时机 |
|---|---|
| 我受到伤害后 | `{ player: "damageEnd" }` |
| 我造成伤害后 | `{ source: "damageEnd" }` |
| 我造成伤害时（改数值） | `{ source: "damageBegin1" }` |
| 我受到伤害时（改数值） | `{ player: "damageBegin3" }` |
| 有人进入濒死 | `{ global: "dying" }` |
| 我杀死人时 | `{ source: "dieBegin" }` |
| 我出牌阶段开始 | `{ player: "phaseUseBegin" }` |
| 我回合结束 | `{ player: "phaseJieshuBegin" }` |
| 任意角色回合结束 | `{ global: "phaseJieshuBegin" }` |
| 我的判定牌生效前 | `{ player: "judgeFixing" }` |
| 我用【杀】指定目标后 | `{ player: "useCardToPlayered" }` |
| 我成为别人牌的目标 | `{ target: "useCardToTargeted" }` |

> [警告] `useCardToPlayered` / `useCardToTargeted` / `useCardToTarget` 三个很像，别混：
> `useCardToXXX` 系列是**对每个目标各建一个事件**的，其中 `next.player` = 用牌者、`next.target` = 当前目标（`src/noname/library/element/content.ts:10074-10078`）。
> - `{ target: "useCardToTargeted" }` = 我成为目标（**最常用**）
> - `{ player: "useCardToPlayered" }` = 我是用牌者
> - `useCardToTarget` 是「目标结算阶段」，和「成为目标」不是一回事

### 3.4 `trigger` 的四种角色（role）

`trigger: { 角色: "时机名" }`，角色决定「事件里的谁」等于技能拥有者：

| role | 含义 |
|---|---|
| `player` | 事件的 `event.player`（受影响者）是自己 |
| `source` | 事件的 `event.source`（来源）是自己 |
| `target` | 事件的 `event.target`（目标）是自己 |
| `global` | 全局时机，任何人触发都通知自己 |

一个技能可以监听多个时机：

```js
trigger: {
  source: "damageBegin1",
  player: "damageBegin3",
},
```
真实实例：`mbjieyuan`（竭缘）— `extension/整合包/character/character.js:31-34`。
注意：同时监听多个时机时，用 `event.triggername` 在 `filter` 里区分是哪个时机触发的（同文件 `:51`）。

### 4.0 最省事：游戏内置的扩展编辑器（可以不写代码）

> [提示] **一个小技巧**：编辑器里的「姓名」输入框其实要填 **`武将id|中文名`** 这种格式，例如 `mydiy_libu|李逵`。

### 4.1 几种落地方式对比

| 方式 | 难度 | 会被游戏更新覆盖吗 | 推荐度 |
|---|---|---|---|
| **游戏内置编辑器**（§4.0） | 低 | 不会（导出为独立扩展） | [重点][重点][重点][重点] 新手首选 |
| **写一个扩展包**（`extension/你的DIY/`） | 中 | **不会**，独立文件夹 | [重点][重点][重点][重点][重点] 推荐 |
| 改 `character/diy.js`（构建产物，9775 行） | 低（直接加，改完重启即生效） | **会**（属官方包内容） | [重点][重点] 仅适合临时试验 |
| 改 `src/character/diy/*.js` 再重新构建 | — | — | [重点] **本包内不可行** |

> [警告] **重要**：成品包运行时加载的是 `character/diy.js`（构建产物单文件），`src/` 目录**不会**被加载。
> 依据：`src/noname/init/import.js:9-10` —— 已在 `moderned_characters` 名单里的包走 `/character/<name>` 而不是 `/character/<name>/index`；
> 而 `game/config.json:239` 的 `moderned_characters` 包含 `"diy"`。
> 所以**改 `src/` 不重新构建 = 完全无效**。而且这个整合包**根本没有构建工具链**：
> `package.json` 的 scripts 只有 `start` / `packageWin64` / `packageWin32` / `packageLinux`（打包成 exe），
> 没有 vite/tsc 构建脚本，也没有 `vite.config.*`，`node_modules` 里没有 vite / typescript。
> 换句话说：**改 `src/` 这条路在这个包里是死的**，不要采用。

**为什么推荐扩展**：
- 扩展是游戏**官方支持的加载机制**，放在 `extension/` 下自动被扫描。
- 扩展武将自带开关，且加载时**自动把扩展名加进启用列表**：
  `src/noname/init/loading.js:336-340` → `lib.config.characters.add(extension[0])`。
- 扩展武将的头像/音效默认就从扩展自己目录取（`loading.js:308,313`），不用去动 `image/`。
- 出问题只影响自己一个文件夹，删掉就干净了。

### 4.4 怎么装进游戏

游戏内置了一个**拖拽导入扩展**，它的说明是：

> 无名杀 windows 电脑版专属扩展，把 zip（离线包，扩展或素材压缩包）拖入到游戏内即可导入
> — `某扩展目录/README.md:1`

步骤：
1. 把扩展文件夹压成 **zip**。**推荐 zip 根目录直接就是 `extension.js` + `info.json` + 图片**（不要多套一层父文件夹）——拖拽导入类扩展按「最短路径」找 `extension.js` 来推断扩展根。它也能识别一层文件夹嵌套，但何必冒险。
2. 打开游戏，**把 zip 直接拖到游戏窗口里**，按提示选择导入为「扩展包」。
3. 按提示重启游戏。

> 拖拽导入类扩展也能直接拖**单个 `extension.js`**（该扩展的 `extension.js`）。

[警告] 三个易错点：
- 该拖拽导入扩展本身需要在「扩展」设置里**启用**才会生效。当前 `game/config.json:260` 的启用列表是
  `["某个 UI 皮肤扩展", "某个大型扩展", "某个搜索类扩展", "某个界面扩展", "某个换肤扩展", "某个皮肤切换扩展", "某个工具类扩展", "整合包"]`
  —— **没有它**，所以第一次用要先在「扩展」界面把它勾上。
- **也可以直接手动把文件夹拷到 `extension/` 下**（免压缩、免拖拽）。但注意：手动放进去之后，仍然要到游戏内「扩展」界面里**启用**它——`lib.config.extensions` 才是启用开关（`src/noname/game/index.js:6411`）。
  拖拽导入的好处是会自动帮你启用（该扩展的 `extension.js`）。
- 如果装了桌面外壳类扩展，它有一个「扩展文件改变重启」选项，会监听 `extension/` 目录，`.js` 一改就自动重启游戏（该扩展的 `extension.js`），调试时很方便。

### 4.5 装好之后，怎么让武将真的出现

这里有两层开关，**容易混淆**：

| 层级 | 默认状态 | 在哪开 |
|---|---|---|
| ① **扩展本身** | **默认关闭**。游戏扫描到 `extension/<名>/extension.js` 只会登记它，并写入 `extension_<名>_enable = false`（`src/noname/init/index.ts:654-656`） | 主菜单 →「**扩展**」页签 |
| ② **扩展的武将包** | 扩展一旦启用，引擎会**自动**把扩展名加进 `lib.config.characters`（`src/noname/init/loading.js:336-340`） | 主菜单 →「**武将**」页签（一般不用手动开） |

所以完整的「从零到能选」流程：
1. 装好扩展（拖拽或手动拷贝）→ **重启游戏**。
2. 主菜单 →「扩展」→ 找到你的扩展 → **开启** → **再次重启**。
3. 主菜单 →「武将」→ 找到你的武将包 → 确认已开启（通常已自动开）。
4. 开一局身份模式，选将框里应该就能看到你的武将了。

**排查顺序**：看不到武将时，先查 ①（扩展没开是最常见原因），再查 ②。

另外注意：本整合包默认配置 `game/config.json:210-234` 的 `characters` 列表**不含 `diy`**——那是官方内置的 DIY 包（`character/diy.js`），和你自己的扩展无关，别混淆。

## 第 5 节 · 避坑清单

1. **技能 ID 和武将 ID 全局唯一**。撞名会被 `lib.skill[name] ??= skill` 静默忽略（`src/noname/game/index.js:6135`）。建议统一加前缀，如 `fr_xxx`。
2. **翻译必须写**。`lib.translate` 里没有的技能/武将，游戏里会显示成原始 ID（甚至显示为空白）。
3. **技能描述 `xxx_info` 的 `xxx` 必须与技能 ID 一致**。
4. **`trigger` 写错时机名 → 技能永远不触发，且不报错**。这是最常见的易错点，务必对照 `src/typings/type.d.ts:857-872`。
5. **AI 字段影响很大**。规则写对但没写 `ai`，电脑可能完全不用这个技能。新手可以先不管，但朋友对战体验会差。
6. **`content` 用 `async` 写法**。旧式 `step 0` 语法已废弃（`docs/game-event/index.md:15-17`）。所有玩家交互都要 `await`。
7. **`cost` 的返回值必须写进 `event.result`**，`content` 里通过 `event.cost_data` / `event.targets` 取用（`docs/lib-skill-format.md:103-131`）。
8. **新放进 `extension/` 的扩展默认是「关闭」状态**，忘了在「扩展」页签开启就会「什么都没发生」。改完文件还要**重启游戏**才重新加载。
9. **联机时**扩展武将默认不加载（`connect: false`），且房间可能禁止扩展。
10. **不要改 `name` / 扩展文件夹名**，改了会导致存档里的武将包配置失效。
11. **不要在扩展里写会被其他扩展覆盖的全局配置**。本地整合包里，桌面外壳类与导入类扩展会强制启用自己，整合包类会改 `forbidai_user`、`hp_style` 等（该扩展的 `extension.js`）。
12. **新手不要用 `.ts` 写扩展**。虽然 JIT 支持（`src/jit/service-worker.ts:46-48`，`/extension` 前缀会被拦截编译），但多一层不确定性，纯 `.js` 就够了。
13. **这几个 API 不存在，不要臆测**：`player.gainCards` / `player.loseCards` / `player.discardCards` / `get.mark`。
    正确写法是 `player.gain({ cards })`、`player.lose({ cards })`、`player.discard({ cards })`；标记相关 API 全在 player 上（`countMark` / `addMark` / `removeMark` / `setMark`）。多人批量用事件 `game.loseAsync({...}).setContent("gaincardMultiple")`。
14. **`subSkill` 的子技能不会自动拥有**，必须写进 `group`（见 §3.2(f)）。
15. **`trigger` 的 role 是全等比对**：`player` / `source` / `target` 分别对应 `event.player` / `event.source` / `event.target`，身份不符合就不触发（`src/noname/library/index.js:11029`）。

## 第 6 节 · 源码在哪：GitHub 仓库 vs 本地打包版

**官方仓库**：[libnoname/noname](https://github.com/libnoname/noname)（GPL-3.0，5103 star，默认分支 `main`，官网 noname.pub）。

**版本对应**：仓库有 tag `v1.11.5.2`，与本整合包的版本号**完全一致**。所以本地源码就是上游该版本的代码。

**布局差异（重要）**：上游是 pnpm monorepo，本地整合包是**构建打包后的扁平结构**。对照关系：

| 上游仓库（tag v1.11.5.2） | 本地整合包 | 说明 |
|---|---|---|
| `apps/core/` | `src/` | 核心源码。例：上游 `apps/core/character/standard/skill.js` ↔ 本地 `src/character/standard/skill.js` |
| `apps/electron/` | `<无名杀目录>/` | Electron 壳（`main.js`、`resources/`…） |
| `apps/mobile/` | — | 手机版，本包没有 |
| `docs/` | `resources/app/docs/` | 文档，路径一致 |
| `packages/` | — | 构建/共享包，打包后被消除 |
| （构建产物） | `character/*.js`、`card/*.js` | **游戏运行时真正加载的文件** |

**实践结论**：
- **写 DIY 武将不需要碰 GitHub**。看懂本指南 + 本地 `docs/` 就够了。
- 需要查「某个 API/字段的最原始定义」时，上 GitHub 搜比在 9775 行的构建产物里翻快得多。
- 但**改代码时注意**：运行时读的是 `character/*.js`（构建产物），不是 `src/`。所以不要以为改了 `src/` 就生效。
- 本地比最新版落后一个小版本（最新 tag 是 `v1.11.6`）。如果以后升级游戏，自己写的扩展通常不受影响（扩展是独立目录）。

**许可证提醒**：无名杀是 **GPL-3.0**。自己写着玩没问题；若要公开发布自己的扩展，注意遵守 GPL（开源）。整合包本身也声明「软件完全免费，禁止倒卖」。

## 第 7 节 · 做出来的武将通用吗？

这是最需要先明确的问题。分三层看。

### 7.1 整合包 vs 官方仓库：核心是同一份代码

**整合包不是另一个游戏**，它是「官方无名杀 + 预装的第三方扩展 + 图片/语音素材 + 一套预设配置 + Electron 打包」。

已验证的证据：
- 本地 `src/character/standard/character.js` 与上游 tag `v1.11.5.2` 的 `apps/core/character/standard/character.js` **同为 3239 字节，内容逐字一致**。
- 本地 `game/updateLog.md` 开头就是 `# v1.11.5.2更新内容`，与官方版本号一致。
- 官方仓库里也有 `apps/core/extension/` 目录，但只有游戏自带的原生 play（boss/cardpile/coin）；整合包 `extension/` 下那 10 个（某个 UI 皮肤扩展、某个大型扩展、某个界面扩展、某个换肤扩展、某个工具类扩展、某个皮肤切换扩展、某个搜索类扩展、某个拖拽导入扩展、某个桌面外壳扩展、整合包本身）都是**社区第三方扩展**，不在官方仓库里。

所以：**你写的扩展运行在官方内核上，不是运行在「整合包」这个私有平台上。** 这是通用性的基础。

### 7.2 决定通用性的真正因素：你用了哪一代 API

扩展的结构（`extension.js` + `package.character/skill` + `trigger/content`）是**官方标准格式，跨版本跨平台通用**。
但**方法调用的写法**有一个分水岭：

| 写法 | 例子 | 兼容性 |
|---|---|---|
| **旧式·位置参数** | `player.gain(cards, "gain2")`<br>`player.damage(source, 2, "fire")` | **新老版本都能跑** [通过] |
| **新式·对象参数** | `player.gain({ cards, animate: "gain2" })`<br>`player.damage({ source, num: 2, nature: "fire" })` | **只有较新版本支持** [警告] |

依据（都在引擎源码里查过）：

1. **本版本两种都支持**：`player.gain()` 内部有两个分支——对象参数走 `Object.assign(next, params)`，否则走旧式逐参数解析（`src/noname/library/element/player.js:8540` / `:8554`）。
2. **官方文档明确承认存在「不支持对象参数的旧版本」**：
   > 旧式不定参数目前仍受支持。
   > 如果扩展需要兼容尚未支持对象参数的旧版本，应继续使用旧式调用，或明确提高扩展所需的最低本体版本。
   > — `docs/player-event-object-parameters-migration.md:479, 488`
3. **它是个很新的机制**：对象参数的文档是 2026-08-01 才进主线的（提交 `0a2d671`，PR #4159）。
   更直接的证据：我查了官方 tag **v1.11.0** 的 `docs/` 目录——只有 `async-guide.md`、`audio-guide.md`、`how-to-start.md`、`skin-guide.md` 四个文件，
   **没有** `player-event-object-parameters.md`、也没有 `game-event/`、`lib-skill-format.md`、`step-to-async-guide.md`。
   也就是说这一整套事件系统/对象参数的文档是 v1.11.x 中后期才补上的。

> [警告] 「对象参数从哪个 v1.11.x 开始支持」没有逐版本核对过。
> 保守结论：**凡是 2026 年 8 月之前发布的版本，都不要假定它支持对象参数。**

#### 版本兼容边界表（扩展作者最该看的一张表）

`lib.version` 的来源：`game/update.js:2` 的 `window.noname_update.version` → `lib.version`。本包是 `"1.11.5.2"`。

| 写法 | 最低版本 | 在更老版本上会怎样 |
|---|---|---|
| 旧式位置参数 `gain(cards, "gain2")` | 远古就有 | 正常 [通过] |
| **对象参数** `gain({ cards, animate })` | **v1.11.3**（2026-04-01） | **静默失效**——不报错，牌直接不摸/不获得 [警告] |
| `async content(event, trigger, player)` | v1.10.6 | 不走异步等待，结算错乱 |
| `cost(event, trigger, player)` | v1.10.11 | 被忽略，退回默认确认框 |
| `getIndex(...)`（一时机多触发） | v1.10.11 | 被忽略，只触发一次 |
| `function*` generator content | — | v1.11.1 起**只在兼容模式**下可用，已废弃 |
| `content` 用 `"step 0"` | 远古 | 仍可用，但官方已标「待废弃」 |
| 数组 content（新语义） | v1.10.15 | 旧语义不同 |
| `import { lib, ... } from "noname"` | 需客户端支持 importmap | 解析失败 → 扩展整体加载不了 |
| `import ... from "../../noname.js"` | 无门槛 | **最稳**，推荐 [通过] |

> [提示] **import 用相对路径更保险**。本包自带的扩展就是这么写的：
> `extension/整合包/extension.js:1` 和 该扩展的 `extension.js` 都是 `from '../../noname.js'`。
> 这比 `from "noname"` 少一个「客户端支持 importmap」的前提。

> [易错] **真实失败案例**：`extension/整合包/character/character.js:3` 写的是
> `export const packs = (lib.version == '1.11.4.1') ? {...} : {}`
> —— 用 `==` 精确比较版本。本包是 1.11.5.2，不等于 1.11.4.1，于是 `packs` 变成空对象，
> **那个扩展在本版本里一个武将都不会加载**。
> **教训：永远不要用 `==` 比版本号。** 要限制最低版本就自己写版本比较函数，或写 `>=` 之类。


### 7.3 三条实用规则

**① 想最大兼容 → 用旧式位置参数写。**
虽然新版官方推荐对象参数，但旧式在新版里依然有效（有兼容分支）。用旧式，你的扩展就能同时跑在老版本和新版本上。
代价是可读性差一些。

**② 只跟核心 API 打交道 → 不依赖整合包。**
```js
import { lib, game, ui, get, ai, _status } from "noname";
```
只要不使用清单以外的内容，扩展就与「整合包特有内容」无关。**反例**：调用 `某个界面扩展`/`某个 UI 皮肤扩展` 提供的函数，或者读 `lib.config.extension_某个界面扩展_xxx`，这些在别人的游戏里都不存在。

**③ 素材要跟着扩展一起走。**
头像（`extension/<扩展名>/<武将id>.jpg`）、阵亡语音（`audio/die/`）、技能语音，都得打进 zip。否则别人的游戏里武将没有图。

### 7.4 一句话总结

> **扩展格式是通用的；能不能跑，取决于你用了哪一代 API，以及对方游戏的新旧程度。**

给朋友分发时，稳妥做法是**用旧式写法 + 只用核心 API + 素材打包 + 附一句「建议游戏版本 v1.11.5 以上」**。
这样既能在整合包里跑，也能在官方包上跑。

## 第 8 节 · 手机 + 联机 + 互相 DIY 武将

这一节针对「几个人各自 DIY 了武将，想在**手机联机**时互相玩到」这个场景。所有结论都在源码里查证过。

### 8.1 手机端怎么装扩展

**好消息：手机可以直接在游戏内导入 zip 扩展**，不需要电脑、不需要拷文件、不需要改 APK。

三条官方路径（都在游戏内菜单）：

| 路径 | 入口 | 适用 |
|---|---|---|
| **① 导入扩展** | 「扩展」→「导入扩展」→ 选 zip 文件 | [重点] **给别人分发自制扩展就用这个** |
| ② 获取扩展 | 「扩展」→「获取扩展」（在线下载） | 只对镜像站上已有的扩展有效 |
| ③ 制作扩展 | 「扩展」→「制作扩展」 | 在手机上直接做，导出 zip |

路径 ① 的代码依据：`src/noname/ui/create/menu/pages/exetensionMenu.js:2385-2451` 走文件选择器 → `game.importExtension`（`src/noname/game/index.js:3267-3380`）。它只需要 `game.readFile` 存在，而**手机端（cordova）有**这个函数（`src/noname/init/cordova.js:272-293`），所以可用。

**扩展在手机上的存放位置**：

| 平台 | 位置 |
|---|---|
| 安卓 | `/storage/emulated/0/Android/data/<无名杀包名>/extension/<扩展名>/` |
| iOS | 无名杀的 Documents 目录下同构 |
| 电脑 | `resources/app/extension/<扩展名>/` |

依据：`app/index.js:67-71, 106-108` + `src/noname/init/cordova.js:15, 326, 367, 399`。

**平台能力差异**（无需记忆，了解即可）：

| 能力 | 电脑版 | 安卓 | iOS | 纯静态网页 |
|---|---|---|---|---|
| 拖拽 zip 导入 | [通过]（某个拖拽导入扩展扩展） | [错误] | [错误] | [错误] |
| 游戏内「导入扩展」 | [通过] | [通过] | [通过] | [错误] |
| 游戏内「获取扩展」 | [通过] | [通过] | [通过] | 只能跳网盘 |
| 文件系统访问 | `fs` | cordova | cordova | [错误] 全无 |

> [警告] **「某个拖拽导入扩展」是电脑版专属**（`某扩展目录/README.md:1`），手机上完全跑不了——它直接 `require("fs")` 和 `@electron/remote`。所以手机分发**不要**指望拖拽，要用游戏内的「导入扩展」。

### 8.2 联机要满足的条件（硬约束）

#### ① 扩展必须显式声明 `connect: true`

`src/noname/init/loading.ts:232` 一行决定生死：

```js
if (!extension[5] && lib.config.mode === "connect") return;   // 联机模式下直接跳过整个扩展
```

`extension[5]` 就是 `extension.js` 默认导出对象的 `connect` 字段。没有它，联机时扩展**根本不会被加载**。
（本包自带的「整合包」扩展就是 `connect: false`，见 `extension/整合包/extension.js:155`。）

#### ② 扩展的武将包也要标 `connect`

仅仅扩展能加载还不够，武将包本身也要声明才能在联机将池出现：

`src/noname/init/loading.ts:139-141`
```ts
case "connect":
    lib.connectCharacterPack.push(name);
```

→ 联机将池的构建链：`lib.connectCharacterPack` →（减去黑名单）→ `lib.configOL.characterPack`（`src/noname/game/index.js:7940-7944`）→ `get.charactersOL()`（`src/noname/get/index.js:1991-2015`）→ `game.initCharacterList()`（`src/noname/game/index.js:160-166`）。

**现成的成功范例**：`extension/某个大型扩展`。它的说明里明写「本扩展武将可以联机时使用」（该扩展的 `extension.js`），写法是：

```js
// ① 扩展顶层
return {
  ...,
  package: {
    character: myPack,   // myPack 是武将包对象
    ...
  },
  connect: true,         // extension.js:8753
};

// ② 武将包对象本身
var myPack = {
  name: 'myPack',
  connect: true,         // extension.js:1671  ← 关键
  character: {...},
  characterSort: {...},
  characterTitle: {...},
};
```

某个大型扩展还额外写了一段**联机同步**代码（`extension.js:8666-8679`），在 `lib.message.server.init` 时把武将包数据发给所有客户端。如果你想让**没装扩展的人也能看到你的武将**，需要这层；如果所有人都装了同一份，就不必。

#### ③ 每个人都得装，**房主尤其不能漏**

框架**不做武将数据下发**。联机的实际流程是：

1. 每个客户端各自从自己的硬盘加载 `lib.character`（`src/noname/init/index.js:565-567`）。
2. **选将池由房主构建**：房主遍历自己本地的包（`src/mode/identity.js:2631-2639`），生成一份**武将 id 列表**广播给大家。
3. 各客户端用这份 id 列表在本地渲染选将按钮（`src/noname/library/element/content.js:7734-7753`、`src/noname/ui/create/index.js:3389-3390`）。

由此推出两条硬规则：

> **规则一：房主没有的武将，所有人都选不到。**（因为池子是房主建的）
> **规则二：非房主没装的武将，选到就是坏的。**

「坏的」具体长什么样（不是崩溃，是**静默残废**）：

| 环节 | 表现 | 依据 |
|---|---|---|
| 找武将数据 | `get.character(id)` 兜底返回 `isNull: true` 的空对象 | `src/noname/get/index.js:1345-1365` |
| 名字 | `get.slimName` 取不到翻译 → **返回空字符串** | `src/noname/get/index.js:3083-3104` |
| 体力 | `info.hp` 是 undefined → 显示 **0 血** | `src/noname/library/element/player.js:3489-3511` |
| 技能 | `player.addSkill` 里 `if (!info) return;` → **静默跳过，无报错** | `src/noname/library/element/player.js:11253-11256` |

所以结论是：**N 个人玩 → N 台手机都要装同一份扩展，并且都要启用。**

（唯一例外：扩展自己写数据下发。现成做法只有 该扩展的 `extension.js` 那样 hook `lib.message.server.init` 把包对象发给客户端——**这是扩展自己写的，框架不提供**。）

#### ④ 武将 / 技能 id 不能撞

多人 DIY 最容易遇到的陷阱。加载时如果 id 已存在，**后来的会被静默丢弃**，只打一行 `duplicated` 日志：

- 武将重复：`src/noname/init/loading.js:201-227`
- 技能重复：`src/noname/init/loading.js:386-391`

> **所以每个人 DIY 时都要给 id 加自己的前缀**，比如 `gh_`（某人的缩写）。否则同一局里只有先注册的那个版本生效。

#### ⑤ 联机武将包默认是「黑名单」制，DIY 包默认被关

这一点容易颠倒，代码是这样的（`src/noname/ui/create/menu/pages/characterPackMenu.js:108-137, 194`）：

- `lib.config.connect_characters` 存的是**联机时被关闭的武将包**
- 界面里一个包「勾上」= 不在这个名单里（`:194` `connectMenu ? !lib.config.connect_characters.includes(mode) : ...`）
- 本包默认值：`["old", "diy", "key", "collab", "offline", "standard"]`（`game/config.json:257`）

**也就是说：默认联机时官方 DIY 包是关着的**，需要在「联机 → 武将」界面手动打开。（你自己的扩展包走的是另一个开关 `extension_<扩展名>_characters_enable`，见 `characterPackMenu.js:111-117`。）

#### ⑥ 房主不要开启「禁止扩展玩家进房」

房主本地有个开关 `check_extension`（「禁止扩展玩家进房」，默认关）：

- 定义：`src/noname/library/index.js:7569-7573`
- 拒绝逻辑：`src/noname/library/index.js:12306-12307`
- 客户端弹窗：`src/noname/library/index.js:13599-13606` —— 提示「房间禁止使用扩展！是否关闭所有扩展？」，点确定会**把所有扩展关掉**，等于放弃 DIY 武将。

另外注意：客户端对房主只上报一个**布尔值**（"我有没有启用任何扩展"，`library/index.js:12721`），房主也只判断真假。**引擎不比对扩展名、顺序或版本**——所以「我装 A、你装 B」不会被拦下，只会在对局中表现为对方缺数据（就是 ③ 里的"空武将"）。

#### ⑦ 所有人游戏版本必须一致

`check_versionLocal` 默认开启，校验 `config.versionLocal != lib.version` 就拒绝加入（`src/noname/library/index.js:12302-12305`，上报在 `:12720`）。另外 `versionOL`（当前 `27`）也要求一致（`library/index.js:31`、`:12298-12301`）。

**这意味着所有人的无名杀版本必须完全相同**——不只是"都 ≥ 1.11.3"。所以：确认版本时，要确认**一模一样**。

#### ⑧ 联机需要一台「大厅服务器」

[警告] 注意：本包根目录那个 70MB 的 `noname-server.exe` **不是联机大厅**，只是个静态文件服务器（express，端口 8089，无 WebSocket，见 `noname-server.js:64, 243`）。

无名杀的联机要连大厅地址（`hall_ip`，`src/noname/library/index.js:7527-7531`）。不过 `wss_mode` 的说明里提到「用户填写的 IP 地址」，说明**自建服务器是支持的**：
> 如果你们线下在同一个 WiFi，理论上可以由一台电脑跑大厅服务端，其他人填它的局域网 IP。

**这一环我还没查清楚**（大厅服务端从哪来、怎么搭），属于待确认项。

### 8.3 [警告] 版本风险：一票否决

官方安卓客户端：[noname-shijian-android](https://github.com/nonameShijian/noname-shijian-android/releases)。

但注意官方 README 里的警告：

> 《无名杀十周年》由无名杀 **v1.9.124** 修改而来 …… **无法兼容使用 1.10 以后功能的扩展**
> —— `README.md:59-61`

**如果朋友的手机装的是十周年、清瑶版之类的 fork，我们的扩展会直接失效。**
动手前必须先确认每个人手机上的 `lib.version`（游戏「选项」里能看到）。

### 8.4 落地清单（照做即可）

**准备阶段**
1. **确认版本完全一致**：所有人游戏里「选项」看到的版本号要**一模一样**（不只是"都够新"）。低于 1.11.3 或用的是十周年/清瑶版之类的 fork → 方案要重定。
2. **确认联机方式**：同一 WiFi 面对面，还是远程；准备好大厅服务器地址。
3. **定 id 前缀**：每人一个前缀（如 `gh_`、`zy_`），**所有武将和技能 id 都带上**——避免 §8.2④ 的静默丢弃。

**做扩展**
4. 一个扩展包装下所有人的武将，`extension.js` 顶层写 `connect: true`。
5. `package.character` 里也写 `connect: true`。
6. **API 用旧式位置参数**（见 §7.2），最大化兼容。
7. 头像/语音一起打进包里。

**分发启用**
8. 打包成 zip（电脑上打包，或手机上用「扩展 → 制作扩展」导出）。
9. 每台手机「扩展 → 导入扩展」选这个 zip。
10. 重启 → 「扩展」页勾上 → 再重启。

**开局**
11. **房主**（就是你选将池的那个人）必须装好并且启用——房主没有的武将，谁都玩不到。
12. 房间内「房间设置 → 武将」确认你们的扩展包是开启状态；房主确认没开「禁止扩展玩家进房」。
13. 开打。

> [提示] **第一次务必先单机验证**：先在电脑上单机把武将选出来、每个技能点一遍，确认没有报错。联机时出错会同时影响所有人，且日志难读。
