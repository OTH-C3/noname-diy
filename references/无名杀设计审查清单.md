# 无名杀 DIY · 设计审查清单

> 用途：**阶段 2.2「对比合理性」** 时逐类过一遍。这是给人和模型判断用的，**脚本查不了**。
> 原则：**只报有把握的**。拿不准就问，别自己替用户改描述。
> 每条都写「后果」—— 用户不懂引擎，只说"这样不行"，他不知道为什么。

---

## 一、数值会失真

| 症状 | 后果 | 怎么问 |
|---|---|---|
| X = 全场牌数 / 全场手牌数 | 后期能到几十，一回合打穿 | 「X 大概能到多少？要不要加上限（比如最多 5）」 |
| X = 已损失体力 / 当前体力 | 残血时翻倍，越强越强 | 「这是想鼓励卖血，还是想惩罚低血？」 |
| 「造成 X 点伤害」X 没给上限 | 直接秒人 | 「X 最多能到多少」 |
| 「回复 X 点体力」没提溢出 | 超过上限的部分无效，等于白写 | 「超过上限怎么算」 |

**必须查规则集**：涉及**牌数统计**（牌堆 / 手牌 / 弃牌堆有多少张）→ `无名杀规则集要点.md` 第一章

---

## 二、逻辑自相矛盾

| 症状 | 后果 | 怎么问 |
|---|---|---|
| 「锁定技，你可以…」 | 锁定技是强制的，带"可以"就自相矛盾 | 「删掉'可以'，还是改成非锁定技？」 |
| 「每回合限一次」+「每当…时」 | 前者是主动技口吻，后者是触发技口吻 | 「这是你主动用，还是条件满足就自动发动？」 |
| 「永久」和「直到回合结束」同时出现 | 两个矛盾的作用域 | 「到底哪个」 |
| 「视为你拥有技能 X」但没说 X 是什么 | 无法实现 | 「X 具体是哪个技能」 |
| 两个技能描述完全重叠 | 可能是有意叠加，也可能是复制粘贴错 | 「这两条是故意重复，还是笔误」 |

**必须查规则集**：涉及**技能分类**（状态类 / 触发类）、**锁定技能否带条件** → `无名杀规则集要点.md` 第二章 1–4 节

---

## 三、与规则冲突

| 症状 | 后果 | 怎么问 |
|---|---|---|
| 「受到的伤害减半」 | 伤害是整数，减半必须定取整方向 | 「向上还是向下取整」 |
| 「回合外使用【杀】」 | 默认不允许 | 「靠什么许可它」 |
| 「濒死时…」没说是谁濒死 | 指代不明，实现会完全不同 | 「是"你濒死"还是"任何人濒死"」 |
| 「摸牌阶段改为摸 X 张」+ 场上已有同类改判技能 | 叠加顺序不同，结果不同 | 「和 XX 同时存在时，谁先谁后」 |
| 「无视距离和次数」没说能否被【无懈可击】 | 结算路径不同 | 「这个能被无懈吗」 |

**必须查规则集**：涉及**伤害/回复结算**、**距离与次数**、**濒死流程**、**多技能叠加顺序** → `无名杀规则集要点.md` 第二章 5 节（结算原则）+ 第三章（时机）

---

## 四、时机对不上

| 症状 | 后果 | 怎么问 |
|---|---|---|
| 「每轮开始时」写成「每回合开始时」 | **轮**和**回合**在引擎里是两个概念 | 「是每轮（所有人各走一遍）还是每回合」 |
| 「使用牌后」 | 引擎里有三个相近时机：牌用出去 / 指定目标时 / 成为目标时 | 「是"牌已经用出去了"还是"刚指定目标"」 |
| 「摸牌时」和「摸牌后」混用 | 一个是替换摸牌数，一个是摸完再做事 | 「是改摸牌数量，还是摸完之后再发动」 |
| 技能写了 `trigger` 但时机名不存在 | **技能永远不触发，且不报错** | 回查 `无名杀技能系统.md` §1 时机名清单 |

**必须查**：**任何时机名**都要核 → `无名杀技能系统.md` §1（带 `trigger.player` / `global` / `source` 的归属区别），这一步不必翻规则集

## 五、会让引擎卡死或报错（不用问用户，直接修）

| 症状 | 后果 |
|---|---|
| 「造成伤害后再次发动本技能」没有次数限制 | 死循环，游戏卡死 |
| 「每当有牌进入弃牌堆时…」没排除自己造成的弃牌 | 自我触发，可能爆炸 |
| `filter` 里做有副作用的操作（改 storage、发牌） | `filter` 会被高频调用，状态被改乱 |
| `onremove` 直接 `delete` 存了牌的 storage | 那些牌**永久消失** |

**这类是纯实现问题**，按正确写法做，汇报时提一句「这处我按防御式写法处理了」即可。

## 六、最容易被「想当然」补错的（重灾区，重点看）

**这几条不是描述有问题，是 AI 自己加戏**：

| AI 容易擅自加 | 为什么不该加 | 正确做法 |
|---|---|---|
| 描述没说「限一次」→ 加 `usable: 1` | 描述没写就是**没限** | **不加** |
| 描述没说「必须有牌」→ `filter` 里加前置条件 | 会让技能**变灰点不动** | **不加** |
| 描述说「使用一张牌」→ 收紧成「只能基本牌或锦囊」 | 装备牌本来就能主动使用 | **不加** |
| 描述说「任意张」→ 允许选 0 张 | 通常至少 1 张 | 问清楚 |
| 描述说「每回合」→ 直接写死 `global: "phaseBegin"` | 方向对，但要确认是"每人的回合"还是"自己的回合" | 问清楚 |

**自查方法**：拿描述逐句对照代码，**每一行限制都要能在描述里找到出处**。找不到出处的限制，删掉或去问。

## 七、什么情况必须查规则集（速查）

| 描述涉及 | 查哪里 |
|---|---|
| 牌的数量 / 花色 / 点数分布 | `无名杀规则集要点.md` 第一章 |
| 技能分类、发动条件、消耗 | 第二章 1–4 节 |
| 伤害与回复结算、多技能冲突、结算顺序 | 第二章 5 节 |
| 时机（什么时候能做什么事） | 第三章 |
| **时机名是否合法** | `无名杀技能系统.md` §1（不必翻规则集） |
| 牌名 / 装备效果 | `无名杀规则集要点.md` 第一章 |
| 字段含义与写法 | `无名杀技能系统.md` §3 字段全表 |

**判断口诀**：**「这张牌怎么算」查规则集，「这个技能怎么写」查技能系统。**

## 八、提问的格式

一次问完，别挤牙膏。每条给出**你的判断 + 一个具体建议**，而不是开放式发问：

> 这个 X 我算下大概能到十几，强度会失控。
> 建议加个上限（比如最多 5），或者换成"手牌数的一半"。
> 你倾向哪个？

**不要**：

> X 是怎么算的？（用户答完还得再问一轮）
