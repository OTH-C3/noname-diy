# 卡面识别：把做好的卡面图变成表单

用户手上可能已经有一张做好的武将牌（第三方网站导出的、或自己画的）。
工坊的「卡面识别」让他们不必手打，直接把图交给你认。

## 什么时候走这条流程

- 用户说「识别卡面」「我传了卡面图」「看看这张牌」之类
- 工作区里存在 `<工作区>/.diy-workshop/card-source.json`

## 链路

```
页面：选卡面图（+ 可选立绘原图）→ 裁块放大 → POST /api/card-source 落盘
你：读 card-source.json 里的图 → 认字段 → 写 card-import.json
页面：每 3 秒轮询 /api/card-import → 拿到就填进表单
```

你**只管读图和写结果**，不碰页面。

## 读什么

`<工作区>/.diy-workshop/card-source.json`：

| 字段 | 是什么 |
|---|---|
| `card` | 整张卡面（长边已缩到 1400 以内） |
| `art` | 立绘原图（用户单独发的；可能为 `null`） |
| `parts.group` | 左上势力字，放大 3 倍 |
| `parts.pips` | 顶部勾玉，放大 3 倍 |
| `parts.name` | 左侧竖排文字，放大 3 倍 |
| `parts.skill` | 下部技能区，放大 3 倍 |
| `cardSize` | 原图尺寸 |

**先看放大过的裁块**——竖排小字在原图里只有二十来像素高，放大后才看得清；
看完裁块**再回看整图**，核对各块的位置关系与顺序（裁块可能切到相邻元素）。
用 Read 直接读这些图片路径。

**用户直接在对话里发的图**（没走工坊）：不要让他去开网页，先把图切块放大再看：

```bash
python3 scripts/inspect-card-image.py <卡面图> --out /tmp/card-parts
```

产出的四块与整图与工坊输出一致，之后按下面的规则识别即可。

## 认什么、怎么认

### 势力（读 `parts.group` 或整图左上）

- 认**字**：魏 / 蜀 / 吴 / 群 / 晋 / 神 → `wei` / `shu` / `wu` / `qun` / `jin` / `shen`
- **不要靠配色判势力**——真实卡面的势力框配色跟游戏里并不一致（实测三张卡面都是
  深框浅字，「群」也不发黄）。颜色只能当旁证，字才是依据
- 认出来不是那六个字（例如「特」「魔」）→ 按**自定义势力**处理：
  `group` 留空、把那个字写进 `groupCustom`

### 体力（读 `parts.pips`）

- **勾玉总数 = 体力上限**，数珠子即可，不用认字
- **实心 = 当前体力，空心（只剩轮廓）= 已损失**——卡面常常画的是残血状态
- 输出 `hp` 按 `"<上限>/<上限>/0"`：扩展定义的是上限，开局按满血
- 实心数不等于总数时，在 `note` 里说清楚（例：「卡面画的是残血状态（实心 2 / 共 6）」）
- 数不清就留空并在 `note` 里说明，**不要猜测数值**

### 称号与名字（读 `parts.name`）

竖排两段：**上面笔画细、多为黄/金色的是称号；下面字大的是名字**。

- 常见繁体 → 简体写进 `name` / `title`，**原文另存进 `raw`**
- 人名类繁体照转（「趙雲」→「赵云」）；若是不该动的写法（日文汉字、角色特有异体字），
  保留原样并在 `note` 里点一句

### 技能（读 `parts.skill`）

每个技能 = 技能名 + 效果描述。技能名一般带方框标签，描述跟在后面。

- **描述一字不改**——这是红线，不许润色、不许补全、不许调整标点
- 描述开头的「锁定技 / 限定技 / 转换技 / 觉醒技 / 使命技 / 主公技」等：
  **原样留在 `desc` 里**，同时把对应标记写进 `types`
- 繁体转简体（描述通常本来就是简体，按实际情况看）

### 立绘

- 用户**单独发了** `art` → 告诉用户「立绘已经放进右边裁剪器了，直接调就行」
- **只发立绘、没发卡面**（`card-source.json` 里只有 `art`）→ 也算有效请求：
  这时没有文字可认，你的活儿是**把立绘复制进扩展目录**（`<扩展>/<角色id>.jpg`，
  用 `place-assets.py` 或直接拷），然后在 `card-import.json` 里写上
  `"artSaved": "<保存到的完整路径>"` —— 前端会据此告诉用户「立绘已经就位」
- **不要从卡面上裁立绘**——卡面上的立绘被名字、技能框压着，裁出来是脏的

## 写什么

写到 `<工作区>/.diy-workshop/card-import.json`：

```json
{
  "importedAt": "2026-10-14T07:00:00.000Z",
  "name": "归溟幽灵鲨",
  "title": "生而为一",
  "group": "",
  "groupCustom": "特",
  "hp": "6/6/0",
  "skills": [
    { "name": "双生", "desc": "锁定技，回合开始时，你将你的体力值与已损体力值分配到本回合你的额定摸牌数与手牌上限。", "types": ["locked"] }
  ],
  "raw": {
    "name": "歸溟幽靈鲨",
    "title": "生而為一",
    "group": "特",
    "skills": [{ "name": "雙生" }]
  },
  "note": "卡面画的是残血状态（实心 2 / 共 6），已按上限 6 填。"
}
```

规则：

- **字段都可不写**。页面只在有值时才填，不会清空用户已经填好的内容。
  认不出的字段**直接省略**，不要写空字符串去覆盖
- `group` 只填六个内置值；自定义势力写 `groupCustom`
- `hp` 写成 `"上限/上限/0"`
- `raw` 是**繁体原文**，给用户对照用 —— 认出来的项尽量都留一份
- `note` 用一句人话写清要注意的地方（残血、认不准的项）

## 写完跟用户怎么说

- 让用户**回网页核对**：「识别结果已经填进表单了，回去看一眼」
- `note` 里的内容要当面说（尤其是残血、认不准的项）
- **识别不准的项必须逐项指出**，不要笼统回复「识别完成」
- **竖排艺术字是重灾区**（尤其二字技能名）：草书、异体字很容易认成另一个常用词 ——
  实测把「**帷幄**」认成「**帷幕**」，技能名、id、提示全错，改名返工三轮。
  这类必须**逐字拆分放大**核对（技能名区域再放大一倍看），并且
  **把识别结果连同原图裁块一起交给用户确认**，别只给文字让他凭空判断。

## 用户在对话里贴图时怎么应对

用户可能直接把图发到对话里。**先判断这是哪一种图**：

| 图是什么 | 怎么做 |
|---|---|
| **卡面**（武将牌：有势力字、勾玉、技能文字这些牌面元素） | 走识别流程；**把识别结果复述给用户核对**；再检查还缺什么 |
| **纯立绘原图**（只有人物，没有牌面元素） | 不做识别，直接进裁剪流程（`scripts/crop-avatar.py` 或工坊裁剪器）；**提醒用户再补一张卡面图**，或者请他口述设定 |
| 都不是，或图太模糊 | 直接问这是什么、需要补什么，不要臆测 |

**卡面识别做完必须做两件事**：

1. **把识别结果复述出来** —— 武将名、称号、势力、体力、技能名与描述，让用户逐项核对。
   不要只默默处理：用户看不到你识别成了什么，而艺术字、残血状态、重名技能都是会认错的地方。
2. **检查立绘** —— 如果还没有立绘原图，明确说一句：
   「卡面上的立绘被名字和技能框挡住了，需要你单独发一张立绘原图」。
   已经给过就不再提。

## 红线

- **绝不修改识别出的技能描述**（一字不改），只做繁简转换
- 认不准就**留空并说明**，不许猜
- 不从卡面上裁立绘
