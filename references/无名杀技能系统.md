## 先看这三个易错点（全都不报错，最难查）

### 1. `forResult()` 返回的就是 result 本身，**不要解构**

```js
async forResult() { await this; return this.result; }   // 引擎原样返回 result
```

```js
const { result } = await player.chooseControl(["a", "b"]).forResult();  // 错：result.result 恒为 undefined
const result = await player.chooseControl(["a", "b"]).forResult();      // 对
```

**症状**：技能能发动、框也弹了、也选了，然后**什么都没发生** —— 不报错、没日志、
连战报都没有，因为代码在 `if (!result) return;` 那一步直接返回。
（`chooseToUse` 这类少数事件的 result 里确实带 `result` 字段，所以解构偶尔恰好成立 —— 不要依赖这种巧合。）

### 2. 事件 `content` 一律写 `async`

```js
content(event, trigger, player) {}        // 错：被当成"旧式 step content"，用 new Function 重编译
async content(event, trigger, player) {}  // 对：引擎直接调用
```

重编译时只注入 `{lib, game, ui, get, ai, _status}`，**模块作用域全丢** ——
文件顶部定义的函数 / 常量全变成 `undefined`：

```
ReferenceError: xxx is not defined
```

（`intro.content(storage, …)`、`translate` 里的 `content(storage, …)` 是 **UI 用的**，不受此限，别一起改。）

### 3. `gaintag` 不加 `eternal_` 前缀，牌一移动就被清掉

```js
const tags = card.gaintag.filter(tag => !tag.startsWith("eternal_"));   // 引擎在牌移动处删掉这些
```

**症状**：牌面标记"只在当回合可见"。
`eternal_` **不会自动过期**，效果结束要自己 `removeGaintag`；翻译键要照**全名**写
（`eternal_xxx: "酒"`），否则牌面显示英文 id。

## 1. `trigger` 时机名清单

### 1.1 时机名是怎么生成的（关键机制）

`gameEvent.ts:247-292` 的 `loop()` 是唯一来源：

```ts
const trigger = async (trigger: string, to: number) => {
  this._triggered = to;
  if (this.type == "card") {
    await this.trigger("useCardTo" + trigger);   // 250-251
  }
  await this.trigger(this.name + trigger);       // 253
};
...
await trigger("Before", 1);   // 262  未 finish，_triggered 0→1
await trigger("Begin", 2);    // 264  1→2
// 2 执行 content
await trigger("Omitted", 4);  // 280  已 finish 且 _triggered==1
await trigger("End", 3);      // 282  已 finish 且 _triggered==2
await trigger("After", 4);    // 284  已 finish 且 _triggered==3
```

另外：
- `checkSkipped()` → `this.name + "Skipped"`（`gameEvent.ts:293-304`）
- `cancel()` → `this.name + "Cancelled"`（`gameEvent.ts:685`）
- `neutralize()` → `"eventNeutralized"`（`gameEvent.ts:698`）
- `type == "card"` 的事件额外派生 `useCardToBefore/Begin/End/After`（`gameEvent.ts:250-251`）

因此规则是：

```
触发技能可用时机 = <事件名> + {Before, Begin, End, After, Omitted, Skipped}
card 类事件额外 = useCardTo + {Before, Begin, End, After}
另有一批 event.trigger("字面量") 手工时机（见 1.3）
```

### 1.5 四种 role 的语义

匹配逻辑只有一行：`src/noname/library/index.js:11028-11031`

```js
!Object.keys(info.trigger).some(role => {
  if (role !== "global" && player !== event[role]) {   // 11029
    return false;
  }
  ...
  if (list.includes(triggerName)) { return true; }     // 11038
```

即：**技能拥有者必须全等于 `event[role]`**（`global` 例外，任何角色都算）。

| role | 含义 | 对应事件字段 | 典型写法 |
|---|---|---|---|
| `player` | 技能拥有者 === 事件主体（多数事件里是"动作执行者/承受者"） | `event.player` | `{player:"phaseJieshuBegin"}`（`standard/skill.js:9`）、`{player:"damageEnd"}`（`diy/skill.js:238`） |
| `source` | 技能拥有者 === 事件来源 | `event.source` | `{source:"damageSource"}`（`standard/skill.js:117`）、`{source:"damageEnd"}` |
| `target` | 技能拥有者 === 事件的**单数** `event.target`，即"我成为目标" | `event.target` | `{target:"useCardToTarget"}`（`diy/skill.js:222`）、`{target:"useCardToTargeted"}`（`diy/skill.js:2729`） |
| `global` | 任意角色；技能拥有者只是"旁观/受益者" | 无 | `{global:"phaseJieshuBegin"}`（`standard/skill.js:23`）、`{global:"useCardToTarget"}`（`standard/skill.js:189`） |

对 `useCardTo*` 系列要特别小心：它们由 `content.ts:10054-10091` 的 `_triggerTo()` 逐个目标创建独立事件，
`next.player = player`（**用牌者**）、`next.target = target`（**当前目标**）、`next.targets = 全部目标`（10074-10078）。
所以：
- `{target:"useCardToTargeted"}` = 我是这张牌的**目标**（最常用，`standard/skill.js:2177`、`bingshi/skill.js:2561`…）
- `{player:"useCardToPlayered"}` = 我是**用牌者**（`standard/skill.js:2177`）

而 `damage` 事件里 `next.player = 被伤害者`、`next.source = 来源`（`player.js:8888-8953`），
所以 `{player:"damageEnd"}` = 我受伤，`{source:"damageSource"}` = 我造成伤害（`content.ts:12095` 在 damage content 里触发）。

`trigger` 值可以是字符串或数组，见 `Skill.d.ts:8-24`、`library/index.js:11033-11037`。

## 2. `mod` 支持的全部键名

`mod` 是"锁定技/状态技"的实现方式：`Skill.d.ts:656-662` 明确写明 *"如果有 mod，技能视为锁定技"*。

**消费点统一是 `game.checkMod`**（`game/index.js:9002-9029`）：

```js
checkMod() {
  const name = argumentArray[argumentArray.length - 2];   // 倒数第 2 个参数 = mod 键名
  let skills = argumentArray[argumentArray.length - 1];   // 倒数第 1 个参数 = 技能拥有者
  ...
  const arg = argumentArray.slice(0, -2);                 // 前面的参数原样传给 mod 函数
  skills.forEach(value => {
    var mod = get.info(value).mod[name];
    if (!mod) return;
    const result = mod.call(this, ...arg);
    if (result != undefined && typeof arg[arg.length - 1] != "object") {
      arg[arg.length - 1] = result;                       // 非对象时返回值覆盖最后一个参数
    }
  });
  return arg[arg.length - 1];
}
```

所以**每个 mod 函数的最后一个参数是"累加值"，返回非 undefined 即覆盖它**（`"unchanged"`/`false`/对象参数除外）。
签名 `CheckMod` 见 `type.d.ts:880-882`。

## 3.5 `ai`：什么时候该写

`ai` 是 `SkillAI` **对象**（`Skill.d.ts:1508`，66 个字段），不是函数。
**不写不会报错**，技能照常发动、玩家手操完全不受影响 —— 它只影响**AI 操控这个武将时的决策质量**。

要不要写，看技能类型：

| 技能类型 | 要不要写 | 写什么 | 不写的后果 |
|---|---|---|---|
| 锁定技 / `forced` 触发技 | **不用** | — | 无（发不发由 `forced` 决定，不经 AI 判断） |
| **视为技**（把 X 当【闪】/【杀】/【桃】用） | **要** | `respondShan` / `respondSha` / `respondTao` / `save` | AI 只看手牌，以为你没牌可出 → **不来响应、直接掉血** |
| 免疫 / 无视类（"【杀】对你无效"） | 要 | `nofire` / `nothunder` / `nodamage` / `nodiscard` / `unequip` … | AI 不知道 → 重复做无效动作，白浪费牌 |
| 主动技且有代价（失体力、弃牌） | 建议 | `neg: true`（AI 认为有害，少用）或给 `result` | AI 高估收益 → 乱用 |
| `viewAs` 技能 | 可选 | 引擎会自动从 `lib.card[牌名].ai` 继承一部分（`game/index.js:8731`） | 但 `respondShan` 这类**牌上没有**，仍要自己写 |

**引擎依据**：`get.skillRank()`（`get/index.js:2220`）在 `info.ai` 为空时**跳过全部修饰**，
只算基础分（`enable: "phaseUse"` +0.5、触发时机是阶段 +0.5、`use*` / `source` 类 +0.3…）。
基础分永远为正，所以 AI **不会拒绝使用** —— 只是评得不准。

**实测参照**（本机统计）：官方 3342 个技能里 1322 个写了 `ai`（40%）；第三方扩展 346 个技能里 66 个（19%）；
纯界面类扩展 0 处。

**写法（视为技）**：

```js
"你的技能id": {
	enable: "chooseToUse",
	filterCard: (card) => get.suit(card) === "heart",
	viewAs: { name: "shan" },
	ai: { respondShan: true },   // 没这句，AI 手里没【闪】时不会尝试用这个技能响应
},
```

## 4. `enable` 的全部合法取值

### 4.1 类型层（权威枚举）

`src/typings/type.d.ts:875-877`：

```ts
type EnableSignal1 = 'chooseToUse' | 'chooseToRespond' | 'chooseCard'
type EnableSignal  = 'phaseUse' | EnableSignal1 | EnableSignal1[]
```

即类型上只有 **4 个**：`phaseUse`、`chooseToUse`、`chooseToRespond`、`chooseCard`（后三个还可组成数组）。

### 4.2 运行层（更宽松）

`src/noname/library/index.js:11114-11131`：

```js
const checkEnable = enable => {
  if (typeof enable === "function") return enable(event);   // ← 还支持函数！
  if (Array.isArray(enable))      return enable.some(i => checkEnable(i));
  if (enable === "phaseUse")      return event.type === "phase";   // 注意：按 event.type 判
  if (typeof enable === "string") return enable === event.name;    // 其余按事件名全等
  return false;
};
```

**结论**：
1. `enable` 可以是**函数** `(event) => boolean` —— 类型定义里没有，但运行时支持（`library/index.js:11115`）。
2. `enable: "phaseUse"` 实际判的是 `event.type === "phase"`，不是事件名（`11121-11123`）。
3. 其它字符串按 `event.name` 全等匹配，**理论上任何事件名都能当 enable 用**（类型定义只列了 4 个）。
4. 数组 = 任一满足（`11118-11120`）。

### 6.2 合并规则（`loadCharacter`）

`src/noname/init/loading.ts:118-229`：

- 遍历返回对象的**每个 key**，默认走 `lib[key][key2] = value2`（207 行 `Object.defineProperty(lib[key], key2, ...)`）。
  所以 `skill` → `lib.skill`、`translate` → `lib.translate`、`dynamicTranslate` → `lib.dynamicTranslate`、`card` → `lib.card`…
- 已存在则打日志报重名（222 行）。
- `character` 特殊：`lib.character[key2] = value2`（204），并把技能名加入 `lib.skilllist`（176、184）。
- **`skill` 里以 `_` 开头的技能名会被跳过**（190-192 行），除非该包已被选中或 `character.connect` 为真。
- `translate` 中 key === 包名时存成 `` lib.translate[`${key2}_character_config`] ``（194-195）。
- 扩展（extension）走 `loading.ts:382-401`，逻辑相同但直接写 `lib.skill[skillName] = skillInfo` / `lib.translate[...] = ...`。

### 6.3 翻译键约定

- 技能名 = `lib.skill` 的键 = `player.storage` 的键 = 默认翻译键：`lib.translate[skillName]`
- 技能描述：`lib.translate[skillName + "_info"]`
  - 读取处：`get/index.js:4026`（`skillInfoTranslation`）、`content.ts:4146-4147`（触发技默认 prompt2）
- 标记背景字：`lib.translate[skillName + "_bg"]`（子技能 marktext 写入，`game/index.js:8777-8779`）
- 子技能翻译：`lib.translate[主技能_子技能]`（未设 `name` 时回退主技能翻译，`game/index.js:8769-8773`）；子技能描述写 `` lib.translate[`${iValue}_info`] ``（8774-8776）
- `lib.translate[`${name}_character_config`]`：角色包名对应的配置项文本（`loading.ts:194-195`）

### 6.4 `subSkill` 展开规则（运行时）

## 8. 速查清单（给 DIY 写作的落地结论）

1. **触发技最小骨架**：`{ audio, trigger: {player|source|target|global: "时机名"}, filter, check, async content }`。
2. **时机名 = 事件名 + Before/Begin/End/After**（`gameEvent.ts:247-292`）；完整可用名见 `type.d.ts:858-869`。
3. **`target` role 只对带单数 `event.target` 的事件有效**；卡牌指定目标请用 `useCardToTargeted`（`content.ts:10139`）。
4. **`global` role 不参与身份比对**（`library/index.js:11029`）。
5. **`mod` 必须返回新值才会生效**，且要关注 `checkMod` 最后两个参数的约定（`game/index.js:9017-9028`）。
6. **`enable` 只写 4 个值**（`type.d.ts:875-877`），另外可以用函数（`library/index.js:11115`）。
7. **子技能必须进 `group` 才会被拥有**（`game/index.js:10166-10174` + `Skill.d.ts:592-593`）。
8. **`limited: true` 会自动补 mark/intro/skillAnimation/init**（`game/index.js:8754-8760`）。
9. **`player.storage[skill]` 是技能私有存储**；标记数值用 `countMark/addMark/removeMark`，不要找 `get.mark`。
10. **文档 `docs/lib-skill-format.md:66` 的 `{source: "damageSource"}` 是正确的**，但同文件 67 行 `{target:"useCardToTarget"}` 的示例要注意 `useCardToTarget` 是"目标结算阶段"而非"成为目标"，实战多数场景应写 `useCardToTargeted`。

### 与 `docs/lib-skill-format.md` 的差异/补充

- 该文档 337 行把 `charlotte` 描述为"状态技/特殊隐藏/不常规移除类标记"——**不完整**：`Skill.d.ts:1285-1296` 还说明它是"异能技"标签，不受 `fengyin`/`baiban`/化身/断肠等影响；另有配套的 `superCharlotte`（1297-1298）。
- 该文档未提及 `enable` 可以是函数（`library/index.js:11115`）。
- 该文档未提及 `round` 会**自动生成 `xxx_roundcount` 子技能并塞进 group**（`game/index.js:8783-8815`）。
- 该文档 491 行提到 `arrangeTrigger` 排序——补充：排序键是 `get.priority(skill)`（`priority*100`，`get/index.js:629-633`），`silent` 会加分，`firstDo/lastDo` 直接分队列（`gameEvent.ts:540`）。
- 该文档未提及 `getIndex` / `indexedData` 机制（`gameEvent.ts:542-562`，样例 `standard/skill.js:95`）。
- 该文档 246-272 的 `group/subSkill` 示例缺少"子技能不会自动拥有"这一关键前提。
