# 无名杀规范

> **目的**：写武将扩展时不必再翻引擎源码。
> 每条结论都标了出处（`文件:行号`），可回源核对。
>
> **来源**：官方 v1.11.6 源码、本地 14 个扩展实例、社区调研
> **标注约定**：`[源码]` = 读源码确认；`[实例]` = 从能跑的扩展里看到

## 零、先分清三种内容

| 名称 | 是什么 | 写法 | 位置 |
|---|---|---|---|
| **内置包** | 引擎自带的武将包 | `game.import("character", ...)` | `src/character/<包>/` |
| **扩展** | 玩家自行安装的包 | `export const type = "extension"` | `extension/<扩展名>/` |
| **模式** | 替换或新增玩法 | 另有一套 | `mode/<模式名>/` |

**本规范主要讲扩展**，但角色与技能的写法两者通用 —— 内置包的知识可以平移到扩展。

## 一、扩展的完整字段表

官方"空扩展"就是最小可用扩展，字段全貌见 `noname/init/import.js:99-127` `[源码]`：

```js
{
	name: "扩展名",              // 必须与文件夹名一致
	editable: false,
	arenaReady() {},             // 进入牌局前调用（猴补丁常放这里）
	content(config, pack) {},    // 扩展被启用时调用
	prepare() {},
	precontent() {},
	config: {},                  // 给用户的设置项
	help: {},                    // 设置项说明
	package: { /* 武将 / 卡牌 / 技能 都放这里 */ },
	files: { character: [], card: [], skill: [], audio: [] },
}
```

**关键字段说明**

| 字段 | 作用 | 备注 |
|---|---|---|
| `name` | 扩展名 | **四处必须一致**（见第七节） |
| `connect` | 是否参与联机 | 缺了联机选不到 |
| `arenaReady()` | 牌局准备时 | 猴补丁、全局改写的首选位置 |
| `content(config, pack)` | 扩展启用时 | 适合做初始化 |
| `config` / `help` | 用户设置 | 见第六节 |
| `package` | 包内容 | 见第二节 |
| `files` | 静态文件清单 | 头像、语音文件名列表 |

**官方模板**（游戏内「新建扩展」按钮生成的骨架，`noname/ui/create/menu/pages/exetensionMenu.js:402-424`）`[源码]`：

```js
import { lib, game, ui, get, ai, _status } from "noname";
export const type = "extension";
export default function () {
	return {
		/* 包内容 */
	};
}
```

同时会生成 `info.json` 与 **`README.md`**（官方也建这个文件）。

### 1.1 两种合法的导出写法

**写法 A：ESM 导出**（官方「新建扩展」生成的就是这种）

```js
import { lib, game, ui, get, ai, _status } from "noname";
export const type = "extension";
export default function () {
	return { name: "扩展名", package: { /* ... */ } };
}
```

**写法 B：`game.import`**（第三方大量在用）

```js
import { lib, game, ui, get, ai, _status } from "../../noname.js";
game.import("extension", function () {
	return { name: "扩展名", /* ... */ };
});
```

出处：`该工具类扩展的 extension.js` `[实例]`、`noname/init/import.js:17` `[源码]`

> **`import` 路径完全不同，不要混淆**：
> - 内置包（在 `src/character/`）：`from "noname"`
> - **扩展（在 `extension/`）：`from "../../noname.js"`**

### 1.2 四个挂载点

| 挂载点 | 何时调用 | 适合做什么 |
|---|---|---|
| `precontent()` | 最早 | 注册 hooks、全局猴补丁 |
| `content(config, pack)` | 扩展被启用时 | 初始化、读配置 |
| `prepare()` | 牌局准备 | |
| `arenaReady()` | 进入牌局前 | 猴补丁（**必须幂等**，见 6.8） |

### 1.3 官方 hooks：20 个安全扩展点

`lib.hooks` 是引擎留给扩展的**改写入口**，比直接替换引擎函数稳 `[源码]`（`noname/library/hooks/index.js`）：

```
addGroup  addNature  addSkillCheck
checkBegin  checkButton  checkCard  checkDie  checkEnd
checkOverflow  checkSkillAnimate  checkTarget  checkTipBottom  checkUpdate
refreshSkin
removeSkillCheck
uncheckBegin  uncheckButton  uncheckCard  uncheckEnd  uncheckTarget
```

用法（`NonameHook` 继承自 `Array`，所以有 `add` / `remove`）：

```js
lib.hooks.checkBegin.add("我的唯一标识", () => {
	/* ... */
});
lib.hooks.checkBegin.remove("我的唯一标识");
```

实例：`该工具类扩展的 extension.js` `[实例]` —— 用它加了一个"全选手牌"按钮。

**读扩展自己的配置**：

```js
game.getExtensionConfig("扩展名", "配置键");
```

## 二、package 的结构

官方扩展的 `package` 只有三大分组 `[源码]`（`exetensionMenu.js:356-380`）：

```js
package: {
	character: { ... },   // 角色：character / characterSort / characterTitle / translate ...
	card: { ... },        // 卡牌
	skill: { ... },       // 技能：skill / translate
	intro, author, diskURL, forumURL, version,   // 元信息
}
```

**加了武将的扩展**（`packs` 写法）`[实例]`：

```js
export const packs = {
	character: {
		connect: true,
		character: characters,             // 角色表
		characterSort,                     // 分组（第一层 key = 本 pack 的 name）
		characterTitle: characterTitles,   // 称号
		translate: { ...translates, ...characterSortTranslate, <扩展名>: "<显示名>" },
	},
	skill: {
		skill: skills,                     // 技能表
		translate: translates,             // 技能名与描述
	},
};
```

> **注意**：`game.import("character", ...)` 是**内置包**写法，`export const packs` 是**扩展**写法。
> 两者的字段名基本对应，但外层包装不同 —— 别混用。

## 五、技能条目字段表

从官方 7 个包统计（约 800 个技能），按出现频率排列 `[源码]`：

### 5.1 核心（几乎每个技能都有）

| 字段 | 作用 |
|---|---|
| `trigger` | 触发时机（见 5.4） |
| `filter(event, player)` | 是否触发 |
| `content(event, trigger, player)` | 效果本体，**async** |
| `ai` | AI 决策（`order` / `result` / `effect` 等）。**可省**：不写不影响技能生效、不影响玩家手操；只影响 AI 操控时的决策。**视为技必须写** `respondShan` / `respondSha` / `respondTao`（否则 AI 以为你没牌可出、不来响应）—— 判断表见 `无名杀技能系统.md` 第 3.5 节 |

### 5.2 技能类型与显示

| 字段 | 作用 | 注意 |
|---|---|---|
| `locked` | 锁定技**标签** | **只管 UI 标签**，不决定是否强制 |
| `forced` | 强制发动 | **锁定技必须同时写 `locked` 与 `forced`** |
| `silent` | 不在日志/提示里出现 | |
| `charlotte` | 隐形技能（不显示在武将牌上） | |
| `popup` | 是否弹技能名 | 设 `false` 可静默 |
| `direct` | 直接执行不询问 | |
| `frequent` | 可频繁发动（重置次数用） | 常与 `refreshSkill()` 配合 |
| `limited` | 限定技 | **只写这一个字段就够**，引擎自动补 mark / 「限定技」介绍 / 发动动画 / 存储初始化（`game/index.js:8754-8760`） |
| `zhuSkill` | 主公技 | |
| `juexingji` | 觉醒技 | |
| `zhuanhuanji` | 转换技（阴阳两态来回切） | **加字段远不够，要自己写两套效果**；状态判定 `get/is.js:635`（`Skill.d.ts:1438`） |
| `mark` / `marktext` | 标记 | **`marktext` 不生效**，实际读 `<技能名>_bg` 翻译 |
| `intro` | 技能详情页补述 | `content(storage, player)` 返回 HTML |
| `derivation` | 衍生技能列表。**本机引擎里只用于显示**：详情页列「—— 衍生技能 ——」（`ui/create/index.js:3578`）、按钮名补成「技能名（武将）」（`get/index.js:4016`）、登记 `_status.skillOwner`（`library/index.js:280-300`）。**不会让人获得该技能**，别跟 `subSkill`（真的展开成子技能）混。另：`Skill.d.ts:1359-1361` 的注释写着"来源技能不存在则当前技能被移除"，但本机源码里找不到执行这段逻辑的调用点 | |
| `forceDie` | **死亡后仍可发动**（`Skill.d.ts:464`；使命技失败结算常用，官方用例 `bingshi/skill.js:3552`） | |
| `unique` / `temp` / `fixed` / `vanish` | 技能收纳（`Skill.d.ts:1275-1283`） | `unique` 左慈化身拿不到；`temp` 死亡即移除；`fixed` removeSkill 移不掉；`vanish` resetSkills 直接移除 |
| `charlotte` | 异能技：封印/白板/化身/clearSkills 都动不了它 | 比 `fixed` 优先级还高；`superCharlotte` 永不删除（`Skill.d.ts:1296-1298`） |

### 5.3 主动技专用

| 字段 | 作用 |
|---|---|
| `enable` | 何时可用：`"phaseUse"` / `["chooseToUse","chooseToRespond"]` 等 |
| `usable` | 使用次数限制（`1` = 每回合限一次） |
| `round` | 每轮限几次。**引擎自动生成 `<技能id>_roundcount` 子技能**并挂进 `group`，它自己在 `roundStart` 记账（`game/index.js:8783-8791`）；配套 `roundtext` 改提示语（`Skill.d.ts:635`） |
| `filterCard(card, player)` | 选牌条件 |
| `filterTarget(card, player, target)` | 选目标条件 |
| `selectCard` / `selectTarget` | 选牌/选目标数量 |
| `prompt` / `prompt2` | 提示文字 |
| `position` | 可选牌的位置，如 `"hs"`（手牌与装备） |
| `viewAs` | 视为技的转化目标，如 `{ name: "shan" }` |
| `viewAsFilter(player)` | 视为技的额外条件 |
| `check()` | 默认选中 |

### 5.4 trigger 的写法

```js
trigger: { player: "damageAfter" }                    // 自己是受害者
trigger: { source: "damageAfter" }                    // 自己是伤害来源
trigger: { target: "useCardToTarget" }                // 成为目标
trigger: { global: "useCard" }                        // 任何角色
trigger: { player: ["phaseBegin", "phaseEnd"] }       // 多个时机
```

**role 决定 `event` 里谁是"事件角色"，`player` 永远是技能持有者。**

### 5.5 子技能与组合

| 字段 | 作用 |
|---|---|
| `group` | 引用**独立技能**（需手动补 `sub: true` + `sourceSkill`） |
| `subSkill` | 内联定义**子技能**（自动展开，常用） |
| `inherit` | 继承另一个技能 |
| `global` | 全局技能 |

**经验**：内部拆解用 `subSkill`（省事），要复用或跨武将共享用独立技能 + `group`。

## 五之三、不可触碰的红线

### 5.3.1 技能描述一个字都不许改

**技能名与 `_info` 描述，必须原样照录用户给的文字。**

遇到下面这些情况，**只指出，不动手**：

| 情况 | 正确做法 | 错误做法 |
|---|---|---|
| 有明显的错别字 | 说「这里是不是想写 X」 | 直接改成 X |
| 标点不规范（半角、缺句号） | 提一句 | 一并修正 |
| 措辞啰嗦、不通顺 | 提一句，给个建议版 | 直接改写 |
| 技能名与已有武将重名 | 指出并问是否改名 | 自己改名 |
| 描述里的数值与描述的效果对不上 | 指出矛盾 | 按自己的理解改数值 |

**为什么这条最硬**：技能描述是用户的作品与最终对外展示的文字。
代码写错了可以改，**文案被改动而未说明，用户可能很久都发现不了**，
等发现时已经发出去给一群人用了。

**唯一例外**：用户**明确说**「你看着改」「帮我润色」——这时才动，而且改完要**逐条列出改了哪里**。

## 六、常用写法模式

### 6.0 零件组合实例：官方没有的技能怎么拼

一个整体官方没有的技能，可以拆成零件逐个找现成写法。例：

| 零件 | 现成写法 | 出处 |
|---|---|---|
| 卜算 X | `player.chooseToGuanxing(X)` | 官方卜算类技能 |
| 让玩家选一个牌名 | `get.inpileVCardList(filter)` + `chooseButton` | 官方牌名选择类技能 |
| 视为使用一张牌 | `player.chooseUseTarget(get.autoViewAs({ name, isCard: true }))` | `bingshi/skill.js:1113` |
| 追踪「以此法造成伤害」 | `event.getParent(4).damaged` | 参考官方 `nsjianxiong` |
| 重铸 | `player.recast(cards, callback)` | 官方众技能 |

**拼出来的技能是全新的，零件全是旧的** —— 这就是应对"官方没有"的正解。
四层退让的判断框架见 `SKILL.md` 的「策略哲学」。



### 6.1 视为使用一张牌

```js
{
	enable: ["chooseToUse", "chooseToRespond"],
	filterCard(card) {
		return get.color(card) === "black";
	},
	viewAs: { name: "shan" },
	position: "hs",
	prompt: "将一张黑色手牌当闪使用或打出",
	check() {
		return 1;
	},
}
```

出处：`src/character/standard/skill.js:929-943` `[源码]`

### 6.2 凭空使用一张牌（不走转化）

```js
await player.chooseUseTarget(get.autoViewAs({ name: "wuzhong", isCard: true }), true);
```

出处：`src/character/bingshi/skill.js:1113` `[源码]`

### 6.3 把牌置于武将牌上并打标记

```js
await target
	.addToExpansion(cards, player, "gain2")
	.set("gaintag", ["你的标记id"]);      // 必须同时补翻译，否则牌面显示英文 id
```

取回：`player.getExpansions("你的标记id")`（这些牌的位置是 `"x"`）

### 6.4 到期自动失效

```js
player.addTempSkill("技能id", { player: "phaseAfter" });
```

第二参数相对于**技能持有者**：`{ player: "phaseAfter" }` = 持有者的回合结束时移除。

### 6.5 追踪"以此法造成伤害"

官方 `nsjianxiong` 的套路 `[源码]`（`src/character/diy/skill.js:7411-7430`）：

```js
// 子技能：从伤害事件回溯到技能事件，打个标记
{
	trigger: { source: "damageAfter" },
	filter(event, player) {
		return event.getParent(4).name == "你的技能id";
	},
	async content(event, trigger, player) {
		trigger.getParent(4).damaged = true;
	},
}
// 主技能里读 event.damaged
if (event.damaged) { /* 造成过伤害 */ }
```

> **`getParent(N)` 的层数依赖调用栈**，参考官方最稳；不命中时试 `3` / `5`。**这是最容易出错的地方**。

### 6.6 私有状态存储

```js
init(player, skill) {
	player.storage["技能id"] = [];
},
// 读取时防御式兜底（开局/复活/技能转移都可能让 init 没跑到）
if (!Array.isArray(player.storage["技能id"])) player.storage["技能id"] = [];
onremove(player, skill) {
	// 区分「可丢弃的状态」与「必须归还的资源」
	delete player.storage["技能id"];
},
```

### 6.7 用户设置项

### 6.8 猴补丁（改引擎行为）

放 `arenaReady()` 里，且必须**幂等**（重复加载不能叠加）：

```js
arenaReady() {
	if (lib.skill.某技能.__patched) return;
	lib.skill.某技能.__patched = true;
	/* 改写 */
},
```

### 6.9 主动技 vs 触发技：发动流程差在哪（`cost` 根本不会跑）

**一句话**：`cost` 只在**触发技**里执行；**主动技**写了 `cost` 不会被调用 ——
主动技要"发动前询问"，用 `precontent`。

**为什么**：`cost` 事件是 `createTrigger` 建的（`content.js:4117` 附近）：

```js
} else if (typeof info.cost === "function") {
    const next = game.createEvent(`${event.skill}_cost`);
    next.setContent(info.cost);
```

而主动技（`enable` 型、玩家点按钮发动）走的是 `chooseToUse` 那条路（`content.js:5091` 起），
**那条路不碰 `cost`**。于是会这样：

```js
async cost(event, trigger, player) { ... }        // 永远不会被调用
async content(event, trigger, player) {
    const opt = event.cost_data.option;           // undefined → 崩
}
```

`event.cost_data` / `event.targets` / `event.cards` 全是空的，但 `event.result.bool` 是真，
所以 `content` 照常往下跑，直到读那个字段才炸 —— **报错位置完全指不到真因**
（反馈里那位连改两遍才找到 `cost` 根本没跑）。主动技里要跨阶段传数据，
跨阶段传数据用 `player.storage` 这类确定存在的载体，不应依赖 `cost`。

**发动前询问的正统做法：`precontent`**

`chooseToUse` 里给主动技留了钩子（`content.js:5354`）：

```js
} else if (info && info.precontent && !game.online && !event.nouse) {
    const next = game.createEvent("pre_" + event.result.skill);
    next.setContent(info.precontent);
    next.set("result", event.result);
```

它拿到的 `event.result` 就是这次发动的结果对象。**把 `bool` 置 false 即可取消**：

```js
async precontent(event, trigger, player) {
    const go = await player.chooseBool("确定发动？").forResult("bool");
    if (!go) event.result.bool = false;
}
```

引擎随后在 `content.js:5418` 判断：

```js
if (event.result && event.result.bool && !game.online && !event.nouse) {
    ... player.useResult(event.result, event);      // 到这里才算真发动
}
```

`bool = false` → `useResult` 不执行 → **次数不加、日志不记、useSkill 事件不创建**。
这就是"取消就不消耗次数"最干净的做法（孙权·制衡 / 诸葛恪·黩武那一类手感），
比"先发动再回滚计数"可靠得多。

> **`precontent` 只在非联机执行**（条件里有 `!game.online`）。联机要另给 `content`
> 留兜底路径，不能只靠它。
> 上面行号是本机版本的行号，会随版本漂 —— 认的是那两段代码，不是行号。

### 6.10 复用官方技能：先检索、再判断能不能调

用户说「做成〖剑合〗那样」时，**不要急于复制实现**。三步走：

**第一步：检索，把所有同名版本摆出来**

```bash
node scripts/search-skill.mjs 探锋
# 命中 1 个技能名、3 个版本
# ### 探锋
# - 宗族 · 族陆景   `clantanfeng`   content: 无  viewAs: 有  enable   src/character/clan/skill.js:2005
# - 病逝 · 势夏侯尚 `mbtanfeng`     content: 有  trigger            src/character/bingshi/skill.js:5901
```

同名技能**效果可能完全不同**（探锋的族陆景版是「视为使用一张【杀】」，夏侯尚版是「准备阶段弃牌」——
只是重名而已）。**把候选原样发给用户让他选**，不要自己挑一个。

**第二步：判断能不能直接调**

| 情况 | 能否复用 |
|---|---|
| 标着 `content: 有` | **能**，直接调（见下） |
| 标着 `viewAs: 有` 而 `content: 无` | **不能** —— 它的逻辑写在引擎的「视为使用」流程里，没有独立 content 可调，只能照描述自己复刻 |
| 只有 `trigger` 的被动技 | 一般能调，但先读它的 `filter`：可能依赖触发时机给的上下文 |

**第三步：能调的话怎么调**

```js
const next = game.createEvent("官方技能id");   // 事件名**必须是官方技能 id**
next.player = player;
next.target = target;                          // 或 next.targets / next.cards
next.setContent(get.info("官方技能id").content);
await next;
```

- **事件名必须是官方技能 id**：技能 content 内部常引用自己的子技能
  （例：`jsrgpingtao` 里会 `player.addTempSkill(event.name + "_sha")`），
  名字换成别的，子技能就对不上。
- 传什么参数，按目标技能 `content` / `filter` 实际读什么来给 —— **先读实现，不要猜测**。
- 官方先例：`src/character/diy/skill.js` 有现成写法。

**为什么不整段抄实现**：抄一份，等于把官方那份的行为与版本差异一起接管了。
反馈里那位第一版就是整段复制，反而自己引入了 bug；改成「直接调官方 content」之后才稳。

> 没有引擎源码时，`search-skill.mjs` 仍能列出速查里的候选（只是没有行号与 `content/viewAs` 判断）；
> 速查本身覆盖 3790 个技能名，见 `references/skills/`。

## 七、命名与 id 规范

### 7.1 扩展名必须四处一致

| 位置 | 说明 |
|---|---|
| 文件夹名 | `extension/<扩展名>/` |
| `info.json` 的 `name` | 关闭状态下的菜单项与开关键按它走（`init/import.js:88-101`） |
| `extension.js` 的 `name` | 引擎按它找文件夹、并**强制**把它当武将包名（`init/loading.js:273`） |
| `characterSort` 第一层 key | = 本 character pack 的 name（用 packs 写法时即扩展名） |

**哪一处对不上要紧**（2026-10-10 对源码核对）：

- **文件夹名 ↔ `extension.js` 的 `name`**：**致命** —— 对不上直接加载不到
  （`init/import.js:30-43`）。
- **`info.json` 的 `name`**：对不上则关闭态的开关键与自动导入写的键不一致，
  表现为**开关可能失灵**。
- **`characterSort` 第一层 key**：**不致命** —— 对不上只是这些武将掉进「其他」
  扁平列表、详情页少一行分组（`characterPackMenu.js:266-359`）。仍然照上面的
  规矩写（保持四处一致最省心），但不应视其为「加载失败」级别的红线。

### 7.2 id 要加前缀防撞

**撞名会被静默丢弃**（不报错）。官方角色 id 是无前缀的（`caocao` / `simayi`），
扩展应加自己的前缀，例如 `cs_guotu` / `lu_luojiesi`。

建议前缀来源：扩展名缩写 + 下划线。

### 7.3 characterSort 的两层结构

```js
const characterSort = {
	<pack名>: {                    // 第一层：character pack 的 name
		<分组id>: ["角色id1", "角色id2"],
	},
};
const characterSortTranslate = {
	<分组id>: "分组显示名",
};
```

出处：`src/character/standard/sort.js` `[源码]`

> **第一层 key 到底是什么？** 常见说法是"必须等于扩展名"，**但不准确**。准确说法：
> **必须等于这个 character pack 的 `name`。**
>
> - 用 `package.character` 写法时，引擎会**强制**把 pack name 设为扩展名
>   （`noname/init/loading.js:229` `content.name = extension[0];`），所以两者才刚好相等
> - 走 `game.import("character", ...)` 独立注册的包可以有自己的 name。
>   实例：走 `game.import("character", ...)` 独立注册时，pack name 可以与扩展名不同
>   （常见做法是 pack name 用拼音缩写、扩展名用中文）
>
> 所以：用 `packs` 写法就填扩展名；自己注册内置包就填你给 pack 起的 name。

### 7.4 自定义势力要"注册"，不能裸写字符串

`group` 写内置六个（`wei`/`shu`/`wu`/`qun`/`jin`/`shen`）以外的字符串时，引擎**不报错、
武将也能选**，但会缺三样（2026-10-10 对源码逐条核对）：

| 缺什么 | 表现 | 源码 |
|---|---|---|
| 配色 | 势力字/名字没有颜色光效（`data-nature=""`） | `get.groupnature` 查 `lib.groupnature` —— `src/noname/get/index.js:1408-1412` |
| 长名翻译 | 需要「全名」的地方显示成「XX2」 | `src/noname/library/element/content.js:1186-1194` |
| 势力集合语义 | 不进 `lib.selectGroup`；国战基本用不了、势力数统计有时序差 | `src/noname/library/index.js:14869`、`src/noname/game/index.js:10321-10330` |

**正确写法**：在扩展的 `content(config, pack)` 里（早于武将包注册）调官方 API：

```js
export default function () {
	return {
		name: "我的扩展",
		content(config, pack) {
			// 自定义势力：id / 简称 / 全名 / 颜色（#rrggbb 或 [r,g,b,a]）
			game.addGroup("mo", "魔", "魔族", { color: "#8a2be2" });
		},
		package: { ...packs },
	};
}
```

`game.addGroup(id, short, name, config, type)`（`src/noname/game/index.js:791-820`）会把它
加进 `lib.group`（`type` 为 `default`/`all`）或 `lib.selectGroup`（`select`/`all`），并写
`lib.translate[id]` / `[id + "2"]`；`config.color` 由官方钩子生成配色 CSS 且写
`lib.groupnature[id]`（`src/noname/library/hooks/index.ts:5-38`），`config.image` 注册势力卡图
（`:40-53`）。**`type` 用默认的 `"default"` 更稳**：`select` 会改变神/魔势力的重选逻辑。

> 不注册也不会崩：玩家初始化会 `lib.group.add(this.group)` 兜一把
> （`src/noname/library/element/player.js:3607`），但配色 / 翻译 / 国战仍然缺。
>
> 联机：所有玩家都得装这个扩展，否则对方那边不认这个势力。

### 7.5 国战：归属、多势力与 mode 声明

国战里能用的势力只有五种：魏蜀吴群晋（`lib.group` 默认六种含神与晋，
`src/noname/library/index.js:13762`；晋要玩家装了带晋的玩法才真有用）。
平时 `group` 是**神或自定义势力**的武将，国战里没有这个势力 —— 要么指定归属，要么进不了国战。

| 字段 | 写法 | 作用 | 出处 |
|---|---|---|---|
| `groupInGuozhan` | 角色定义里 `groupInGuozhan: "shu"` | 国战里算蜀（官方神关羽：平时神、国战蜀，`src/character/extra/character.js:7`） | `element/character.js:42` |
| `doubleGroup` | `doubleGroup: ["wei", "qun", "jin"]` | 国战亮势力时挑一个（谋攻篇刘伶三势力，`src/character/newjiang/character.js:245`） | `element/character.js:77`；判定 `get/is.js:313` |

**有一道闸要知道**：对象字段会转成传统 tag 交给国战（`gzgroup:蜀` ／ `doublegroup:魏:群`），
转换时校验**值必须在 `lib.group` 里，否则整个字段被丢弃**（`element/character.js:365`）。
所以自定义势力想写国战归属，必须先按 7.4 `game.addGroup` 注册。

**整个扩展要进国战卡池，packs 的 character 组必须声明 `mode: "guozhan"`**：

```js
export const packs = {
	character: {
		mode: "guozhan",   // ← 少了它，国战里选不到这个扩展的任何武将
		connect: true,
		character: { /* ... */ },
		characterSort: { /* ... */ },
		translate: { /* ... */ },
	},
	skill: { /* ... */ },
};
```

引擎看到它才把扩展挂进 `lib.characterGuozhanFilter`（`src/noname/init/loading.js:279`；
经 `game.addCharacterPack` 的扩展路径同款开关在 `src/noname/game/index.js:6061-6085`）。

### 7.6 宗族：标签与共享效果

出自官方「宗族篇」（`src/character/clan/`）。两个字段配套用：

| 字段 | 写在哪 | 作用 |
|---|---|---|
| `clans` | 角色定义，`clans: ["吴郡陆氏"]`（数组，可归属多个） | 归属某世家；本身**不带机制**，是给宗族技判断「同宗」用的（`element/character.js:147`，tag `clan:` `:289`） |
| `clanSkill` | 技能定义，`clanSkill: true` | 详情页多一个「宗族技」类别标签（`get/index.js:821`） |

**宗族技的效果要自己写**：`trigger` 用 `global` 监听全场事件，filter 里判断目标角色的
`clans` 是否含我的宗族名 —— 官方样例「族泽」（`src/character/clan/skill.js:1203`，
文案：「当你或一名吴郡陆氏角色失去其场上的所有牌后……」）。同宗武将名字前有「族」字前缀
（translate 里 `<武将id>_prefix: "族"`，`src/character/clan/translate.js:4-8`）。

**检查脚本会抓两类**：描述含「宗族」却没标 `clanSkill: true`（警告，第 3 类）；
标了 `clanSkill` 却没有任何角色写 `clans`（错误，跨表一致性 2a-3）。

### 7.7 皮肤路线 B：技能变身（characterSubstitute）

路线 A（skinPath + 玩家手选）之外，皮肤还能被**技能变身** —— 官方〖忠傲〗使命成功换火龙果形态
就是这套（`docs/skin-guide.md:10-110`）。三件套：

**① 在 `content(config, pack)` 里声明替身表**（`lib.characterSubstitute` 的键是武将 id）：

```js
content(config, pack) {
	lib.characterSubstitute["cs_guotu"] = [
		["cs_guotu_fen", ["ext:我的扩展/skin/cs_guotu/谋定天下.jpg"]],
		["cs_guotu_bai", ["ext:我的扩展/skin/cs_guotu/白衣渡江.jpg"]],
	];
},
```

每项 `[皮肤id, 信息格]`：信息格同数组式 character 的第五格，图片用
`ext:扩展名/路径`，阵亡语音可加 `die:…`（空数组则走默认路径 —— 对扩展默认路径没意义，
**图片路径要写**）。写在这里有引擎注释背书（`library/element/player.js:3694-3698`）。

**② 皮肤 id 的显示名**（变身时玩家牌上叫什么，`tempname` 读的就是它）：

```js
translate: {
	"cs_guotu_fen": "谋定天下·郭图",
},
```

**③ 技能里换**：`player.changeSkin(map, "皮肤id")` —— map 定位哪张武将牌
（字符串 = 持有该技能的牌；`{ characterName: "cs_guotu" }` 按 id 定位），
时机由技能逻辑决定（转换技按阴阳状态、使命技按成败，样例见 `docs/skin-guide.md:110-146`）。

**图片只放一份**：路线 A 的 `skin/<角色id>/<形态名>.jpg` 与路线 B 的信息格引用的是
同一张图，不重复放。工坊里给形态填了「变身名」＝该皮肤按路线 B 交付。

### 7.8 武将列传：详情页的生平

数据键 `lib.characterIntro["武将id"] = "生平文字"`（`library/index.js:48`，展示点
`ui/click/index.js:3546`）。官方兵势篇每个武将一篇几百字（`src/character/bingshi/intro.js`）。

**扩展的落笔通路**（两条都确定可行）：

1. packs 里带 `characterIntro: { "武将id": "列传" }`，并在 `content()` 里合并：
   `Object.assign(lib.characterIntro, pack.characterIntro)`；
2. 或直接在 `content()` 里逐条赋值 `lib.characterIntro["武将id"] = "…"`。

注意：数组式角色还有第三条路 —— tag `des:文字`（`get/index.js:1385`），两种形式别混着用。
列传支持 HTML（详情页按富文本渲染）。

### 7.9 动态描述：描述随对局状态实时变

数据键 `lib.dynamicTranslate["技能id"] = (player, skill) => 返回 HTML 字符串`
（`library/index.js:120`，替换入口 `get/index.js:4023` —— 运行时用它替换技能的 `_info` 描述）。
官方兵势篇「驰云」的写法（`src/character/bingshi/dynamicTranslate.js:4-11`）最典型：

```js
dynamicTranslates: {
	potchiyun(player, skill) {
		let s1 = player.storage[skill + "1"];        // 读玩家存储：这条分支用过没有
		let t1 = "1.展示所有与这些牌颜色相同的手牌……";
		if (s1) {
			t1 = `<span style="text-decoration: line-through;">${t1}</span>`;  // 已生效的划掉
		}
		return t1 + t2;
	},
},
```

挂载与列传同款：packs 里带 `dynamicTranslate: {...}`，`content()` 里
`Object.assign(lib.dynamicTranslate, pack.dynamicTranslate)`。

**三条纪律**：① 只改显示，**不改逻辑** —— 效果判断仍以 `player.storage` 为准，不得由描述反推状态；
② 函数必须幂等（每次调用重新算，不能有副作用）；
③ HTML 里别引入与主题冲突的样式，划掉用 `line-through`、强调用引擎已有的 nature 类。

工坊不收这块的表单 —— 内容取决于技能的状态机，**描述驱动**：用户说明
「哪个状态下显示什么」，AI 按本节写函数。

### 8.1 台词与语音：`#` 开头的键

**先纠正一个常见误解**：台词**不会**以字幕形式在游戏里弹出来。
引擎播语音走的是**文件列表**（`game.tryAudio`，`src/noname/game/index.js:2569-2613`）`[源码]`，
全程只播音频文件、不渲染文字。台词文本的去处是**武将详情页** ——
玩家点开武将，「技能台词 / 阵亡台词」按 `#` 键列出来
（`src/noname/ui/click/index.js:3661-3672`、`:3720`、`:4038-4094`）`[源码]`。

所以两件事是分开的：**要"会说话"得有音频文件；台词文本决定"介绍页里写的是什么"。**
只写台词，介绍页有字但不出声；只放音频，有声但介绍页没字。

**台词键的写法**（规格官方 `docs/audio-guide.md`；消费点
`src/noname/get/audio.ts:402` / `:499`）`[源码]`：

| 写在哪 | 键 | 值 |
|---|---|---|
| 技能台词 | `"#<技能id>1"`、`"#<技能id>2"` … | 那一句台词 |
| 阵亡台词 | `"#<角色id>1:die"`、`"#<角色id>2:die"` … | 那一句台词 |

- **键一律加引号**：键里有 `#`，官方与社区都写成 `"#potchiyun1": "…"`
  （取样 `src/character/bingshi/voices.js:2-7`）`[源码]`。
- **键里不带文件后缀**：写 `#wusheng1`，不写 `#wusheng1.mp3`（`docs/audio-guide.md`）。
- **序号从 1 起，而且要连着**：写了 `1`、`3` 却没有 `2`，只有前一句会被认到。
- 键里的「音频地址」是**剥掉默认路径**后的样子 —— 技能默认路径是 `skill/`、
  阵亡是 `die/`，两者都不出现在键里（`src/noname/get/audio.ts:398`、`:495`）`[源码]`。
  只有用 `ext:` 自定义路径时地址才变长，例如 `"#ext:我的扩展/audio/wusheng1"`。
- **一个技能写几句台词，取决于它的 `audio` 字段**（`Skill.d.ts:350`）：
  `audio: 2` 对应 `#<技能id>1`、`#<技能id>2`；`audio: true` 只有一句，
  键是 `#<技能id>`（**不带序号**）。不写 `audio` 时默认值是 `[true, 2]`
  （`docs/audio-guide.md`）—— 但扩展目录里没放音频文件的话，一样不会响。
- 阵亡台词要生效，角色定义里得有 `dieAudios`；**留空数组时引擎会自动补一条**
  `ext:<扩展名>/audio/die:true`（`src/noname/game/index.js:6096-6098`）`[源码]`。

#### 配音文件怎么落地（技能音频）

光有 `audio` 字段不响，还得有**文件**，而且要放对名字：

1. 音频放进扩展目录的 `audio/` 下（`extension/<扩展名>/audio/`），
   **文件名必须是 `<技能id>1.mp3`、`<技能id>2.mp3`** —— 序号与 `audio` 的数字对应，
   第 n 个文件配第 n 句台词。**技能 id 是英文/拼音**（用户填的技能名是中文，当不了文件名），
   所以给文件改名这一步是 AI 干的。
2. 技能上写 `audio: "ext:<扩展名>/audio:<句数>"` —— 两句就写 `"ext:我的扩展/audio:2"`。
   「路径 + 数字」之间是 `:` 不是 `/`，后缀也用 `:`（`:mp3` 可省）（`docs/audio-guide.md`）`[源码]`。
3. 工坊里用户传的音频落在 `<工作区>/.diy-workshop/audio/`，payload 以 `skills[].audioFiles`
   给出绝对路径（第 n 个 = 第 n 句）—— 打包时**复制并改名**进扩展的 `audio/`。

**台词与音频是两件事，缺哪个都行**：只写台词键 → 介绍页有字不出声；只放音频不写台词键 →
有声音但介绍页没字。要"有字又有声"就两样都做，而且**句数要对上**。

`files: { character, card, skill, audio }` 这个清单**引擎不读**（src 里没有消费点：
只有游戏内建扩展编辑器保存时会填，且只填 `audio/die/`）`[源码]`——可以不写。

## 九、打包与分发

**zip 根目录必须直接是 `extension.js`**，不能多套一层文件夹，否则游戏认不出。

```
你的扩展.zip
├── extension.js        ← 根目录
├── info.json
├── README.md
├── 角色id.jpg          ← 头像，350x464
└── character/
    └── character.js
```

**头像规格**：`350 × 464`（对齐官方 `image/character/*.jpg`）`[实例]`

### 9.1 打包后必须报出导出路径（硬要求）

打完包**必须**向用户给出**绝对路径**，不能只说「已打包」：

```
[通过] 导出到：/home/user/工作区/成品/我的扩展.zip
        49.0 KB，4 个文件
```

**同时给源目录** —— 用户想再改的时候得知道源在哪：

```
源目录：/home/user/工作区/扩展源码/我的扩展/
```

**为什么写进规范**：工作区路径常常嵌得很深
（例如 `<某整合包>/游戏目录/resources/app/extension/...`），
只说文件名等于让用户自己去找。**报了路径，用户点一下就装。**

**这一条对工坊模式同样适用** —— 网页上提交的需求，导出的 zip 落在哪个目录，
一样要写清楚。

---

### 9.2 改写已有扩展：只动该动的

**场景**：用户在工坊的「修改已有」里改了一个老武将，要求写回文件。

**原则**：**改动要像外科手术，不像重刷油漆。**

**必须做的四件事**：

1. **先备份** —— 改之前把原文件复制成 `<文件名>.bak`。
   回滚成本是零，不做的代价可能是用户攒了很久的扩展没了。
2. **只改目标字段** —— 用户改了什么就改什么，**不得附带「优化」其他位置**。
   包括：不改格式、不重排顺序、不统一引号、不删注释。
3. **改后回读** —— 打开文件确认改动落盘，并确认**别的武将没被牵连**。
4. **报出改动** —— 改了哪个文件的哪几行、备份在哪、其余未动。

**绝对不要**：

| 做法 | 后果 |
|---|---|
| 整块重写 `character.js` | 丢掉别的武将、注释、用户自己的特殊写法 |
| 用 JSON 序列化覆盖文件名 | 原文件里的函数、注释全没了 |
| 附带统一缩进或引号 | 制造出几百行无关 diff，用户没法 review |
| 改完不验证 | 出现过「编辑成功但内容没落盘」 |

**翻译表 vs 技能代码**：

- 改**名字与描述** → 动 `translate`（安全）
- 改**技能效果** → 动 `content` 等实现字段（**要动就整体重写那个技能对象，
  并说明改了哪些逻辑**，不得只改一半而不说明）

## 十一、扩展的加载机制（决定"为什么必须这么写"）

### 11.1 硬性要求

| 要求 | 后果 | 出处 |
|---|---|---|
| 目录里**必须有 `extension.js`** | 缺了会被直接报错移除 | `noname/library/index.js:5189-5195` |
| 必须导出 `type = "extension"` | 不匹配直接抛错 | `src/noname/init/import.ts:66-70` |
| 目录名 = `extension.js` 的 `name` | 引擎按 name 找文件夹 | `src/noname/init/import.ts:30` |

**`info.json` 不是硬性要求** —— 缺了引擎用兜底值（作者显示"未知"，简介提示"尚未开启"）。

**它只有六个字段**（读入 `init/import.js:89-101`；官方内建扩展编辑器也按这套写盘 `exetensionMenu.js:423-429`）`[源码]`：

| 字段 | 作用 |
|---|---|
| `name` | 扩展名。**必须与文件夹名、`extension.js` 的 `name` 一致**（见 7.1） |
| `intro` | 扩展简介 —— 显示在游戏的扩展菜单里（`game/index.js:3018-3032`） |
| `author` | 作者 |
| `version` | 版本号 |
| `diskURL` / `forumURL` | 网盘链接 / 论坛链接 |

**选将界面的包名**：默认显示扩展名。想自定义，在 packs 的 character 组 `translate` 里
加一条 **key 为扩展名** 的条目 —— 引擎加载时会把 `translate[扩展名]` 写成
`<扩展名>_character_config`（选将界面读的就是它，`init/loading.js:198-200`、消费 `get/index.js:5213`）：

```js
character: {
	/* ... */
	translate: {
		"我的扩展": "自定义包名",
	},
},
```

**`intro` 支持 HTML**：引擎渲染走 `ui.create.div(".text", intro)`
（`exetensionMenu.js:2600`），官方自己的兜底文案就带 `<b>` 标签（`init/import.js:94`）`[源码]`。
所以 `<b>`、`<br>` 这类标签会生效。但**别往里面塞 `<script>`**：
那等于让扩展往游戏界面注入可执行内容，是在做扩展不该有的能力。

**`intro` 是整包级的** —— 它不是某个武将的介绍（武将生平是另一码事，见 `lib.characterIntro`）。
一个扩展只有一个 `intro`，里面所有武将共用。

### 11.2 加载流程（七步）

1. 收集待加载列表：`lib.config.plays` 的官方玩法 + `lib.config.extensions` 的扩展
2. 「自动导入扩展」开启时扫描 `extension/` 下的目录；**未登记的写入 `extension_<目录名>_enable = false`**
3. `importExtension(name)` → 动态 `import()` → 校验 `type` → `game.import("extension", default)`
4. 建菜单项；若 `extension_<name>_enable` 为假 → **到此为止**（不注册 packs、不跑 content）
5. 通过后：落盘带 `init` 的 config → `await precontent(config)` → `prepare` 加入 `lib.onprepare`
6. 开局前：执行 `content`、注册 character/card/skill 包、`arenaReady` 压栈
7. 界面建好后统一 `lib.arenaReady.shift()()`

### 11.3 三个"默认"必须知道

- **新扩展默认是关闭的**（自动导入路径写 `false`），要在「扩展」页手动开启并重启
- **`connect` 缺省或 false 时，联机模式下整个扩展不加载**
  - 注意区分：`connect`（扩展级）不同 `package.character.connect`（武将包是否进联机将池）
  - 实例：分发型与工具型扩展常显式写 `connect: false`（因为它们本身不适合联机）
- **`arenaReady` 可以是函数，也可以是类实例** —— 是类时，原型上所有方法会被逐个压栈

### 11.4 头像的默认规则

不写 `img` 时，引擎按这个路径找（`noname/init/loading.js:257-262`）：

```
extension/<扩展名>/<角色id>.jpg
```

- **文件名必须等于角色 id**
- **350 × 464 是社区通行规格，但引擎本身不校验尺寸**（超了会拉伸或裁切）
- 要放子目录或换格式，必须显式写 `img`（或用数组式的 `ext:` 项）

### 11.5 数组式与对象式两种角色写法

引擎两种都支持（`noname/init/loading.js:234-282`）：

```js
// 对象式（推荐，可读性好，扩展主用）
{ 角色id: { sex: "male", group: "wei", hp: 3, skills: [...] } }

// 数组式（内置包常用，紧凑）
[性别, 势力, 体力, 技能数组, 附加项数组]
```

## 十二、用户设置（config / help）怎么用

`config` 的每个键会变成 `extension_<扩展名>_<键>`；带 `init` 的会落盘为默认值。

**开关 / 下拉**

```js
config: {
	某个开关: {
		name: "显示名",
		init: true,
		intro: "说明文字",
	},
	某个下拉: {
		name: "选项名",
		init: "all",
		item: { all: "全都要", onlyFriend: "只看队友" },
		intro: "选择范围",
	},
}
```

**文本输入**（`input: true` + `onblur` 校验）

```js
config: {
	某项: {
		init: "960",
		name: "宽",
		input: true,
		onblur(e) {
			const v = Number(e.target.innerText);
			if (Number.isNaN(v)) return;
			game.saveExtensionConfig("扩展名", "某项", v);
		},
	},
}
```

**按钮型**（`clear: true` 表示只当按钮、不存值）

```js
config: {
	导入默认设置: {
		clear: true,
		name: "点击导入",
		onclick() { /* ... */ },
	},
}
```

**`help` 普遍没人用** —— 实测 8 个扩展里 7 个是空 `{}`。
说明文字更常塞进 `config` 的 `intro` 或 `package.intro`。

**读扩展自己的配置**：

```js
game.getExtensionConfig("扩展名", "配置键");
```

## 十三、扩展类型速览

社区扩展按"做什么"分几类。下面给的是**类型特征**与**各自值得参考的机制**，
不点名具体扩展 —— 一来避免版权与署名问题，二来具体包会失效、会改名，
写进规范反而误导。

| 类型 | 典型规模 | 值得参考的机制 |
|---|---|---|
| **加武将** | 几百行 | `packs` 两层写法 —— **武将扩展的标准样板** |
| **加卡牌** | 几百 ~ 几千行 | 卡牌定义 + 卡图用 `ext:` 前缀 |
| **加模式** | 几百 ~ 上万行 | `game.import("play")` |
| **工具类**（猴补丁 / 内置技能） | 一千行上下 | `lib.hooks` 用法、`config` 写法 |
| **桌面外壳类** | 几百行 | 输入型配置、错误定位（依赖 Electron） |
| **导入 / 分发类** | 几百行 | worker 解压、安装流程 |
| **整合包** | 几百行 | 预设分发、条件式覆盖 |
| **UI / 皮肤类** | 几万 ~ 几十万行 | 只看入口结构即可，别逐行读 |

**加武将扩展的最小目录形状**（其余类型更简单）：

```
<扩展名>/
├── extension.js          # 入口
├── info.json
├── character/
│   └── character.js      # characters / skills / translates / packs
└── <角色id>.jpg          # 头像放根目录，文件名 = 角色 id
```

**工具类扩展的最小形状**：只有 `extension.js` + `info.json` 两个文件。

**怎么找参考实现**：在你自己装过的扩展里挑一个**同类且能跑起来**的当形状基准即可。
本规范只规定"要件"，不规定"参照哪个" —— 因为能跑的那个可能明天就被作者删了。

### 14.4 `getParent` 的三种参数

```js

event.getParent(evt => evt.name === "x");    // 按函数找
```

默认返回 `{}`；`forced` 类事件返回 `null`。

| 前缀 | 用途 | 例 |
|---|---|---|
| `ext:` | 本地文件系统 | `ext:扩展名/角色id.jpg` |

## 十五、官方工程链路（脚手架、构建与分发）

### 15.1 官方有正式的扩展脚手架

```bash
pnpm init:extension <name> [--author <x>] [--vue]
```

- 模板在 `scripts/extension-template/{default,vue}`
- 生成到 `packages/extension/<name>`

## 十六、素材路径：一锤定音

**这是社区教程里最容易说错的一点。**

引擎的默认规则（`noname/init/loading.js:255-266`）`[源码]`：

```js
if (!character.img) {
	character.img = `extension/${扩展名}/${角色id}.jpg`;
}
if (!character.dieAudios) {
	character.dieAudios = [`ext:${扩展名}/${角色id}.mp3`];
}
```

**结论**：

| 问题 | 答案 |
|---|---|
| 头像默认放哪 | **扩展根目录**：`extension/<扩展名>/<角色id>.jpg` |
| 会自动找 `image/` 子目录吗 | **不会**。要放子目录必须显式写 `img` |
| 语音默认放哪 | `extension/<扩展名>/<角色id>.mp3`，或显式写 `dieAudios` |
| 数组式角色 | `ext:<扩展名>/<角色id>.jpg` 或 `db:extension-<扩展名>:<角色id>.jpg` |

**社区教程里"把图放 `image/character/` 就会自动生效"的说法不准确** ——
那些教程其实在 `precontent` 里**自己拼了 `img` 路径**（例如
`img: extension/<名>/image/character/<id>.jpg`）。是它写的路径生效了，不是引擎找过去的。

**两种做法都行，但要知道区别**：

```js
// 做法 A：图放扩展根目录，什么都不用写（最省事）
extension/我的扩展/cs_guotu.jpg

// 做法 B：图放 image/ 子目录，必须在角色定义里显式写 img
extension/我的扩展/image/character/cs_guotu.jpg
const characters = {
	cs_guotu: {
		sex: "male", group: "wei", hp: 3, skills: ["..."],
		img: "ext:我的扩展/image/character/cs_guotu.jpg",
	},
};
```

**本规范推荐做法 A**（根目录 + 文件名 = 角色 id）：

- 不用写 `img`，少一处出错
- 与官方 `image/character/*.jpg` 的命名约定一致（都是 `<id>.jpg`）
- 几个到几十个武将的小规模扩展完全够用

武将多、或有卡图/语音要分类时，再用做法 B。

**技能语音的路径**（与头像不是一回事，别照搬）：

| 技能里怎么写 | 音频文件放哪 |
|---|---|
| 不写 `audio`（默认 `[true, 2]`） | 引擎去游戏自带的 `audio/skill/<技能id>.mp3` 找 —— 扩展目录里放了**也不认** |
| `audio: "ext:<扩展名>/audio:2"` | 扩展目录下 `audio/<技能id>1.mp3`、`<技能id>2.mp3` |
| `audio: "ext:<扩展名>/audio/<技能id>.mp3"` | 扩展目录下 `audio/<技能id>.mp3` 这一份 |

「路径 + 数字」之间的分隔符是 `:` 不是 `/`，后缀也用 `:`（`:mp3` 可省）
（`docs/audio-guide.md`）`[源码]`。台词文本与音频文件**不是必须成对** —— 见 8.1。

| 取 / 数连接牌 | `player.getConnectedCards()` / `player.countConnectedCards()` |
| 重置 | `player.resetConnectedCards(params)` — `player.js:1177` |

"一张被用掉 → 其余连着的跟着弃"这件事由**全局技能 `_sxrm_connect`** 负责
（`library/skill.js:2276`，玩家看到的名字叫「连接」，`marktext` 为一个锁链符号）。
扩展里只调用上述几个 API 即可，**不要自己写弃置链**。

### 置于武将牌上（"移出游戏"）

`player.addToExpansion(params)` — `player.js:8658`（底层 `$addToExpansion` `:8371`）。
放上去的牌算**游戏外**资源，`onremove` 时必须归还，直接 `delete` 会让它们永久消失
（见「五之三、不可触碰的红线」与避坑清单）。

### 明置手牌

`player.addShownCards(params)` — `player.js:1274`，把这张手牌亮给所有人看。

### 横置 / 连环

角色被横置时 `player.isLink()` 为真，`player.link()` 切换状态。铁索那一套用它。

### 技能归属与按钮立绘（`_status.skillOwner`）

- 技能详情页与技能按钮上的立绘、以及技能名显示成「技能名（武将）」，读的都是**同一张表**
  `_status.skillOwner`（技能名的拼接见 `get/index.js:4016`）。
- 这张表在 `lib.init` 里会被**重建**（`library/index.js:235`），所以想钉住某个技能的归属，
  **`content` 与 `arenaReady` 两处都要写**，只写一处会被冲掉。
- 官方技能是"谁拥有就归谁"自动登记的（`library/index.js:280-300`）。
  想让某技能显示成别的武将：按钮项写成 `[技能id, 武将id]`，或直接改 `_status.skillOwner[id]`。
